🎨 Rendering Performance
1 Component baar-baar re-render ho raha hai. Kya karoge? State / props / context / parent change Profiler → root cause → state placement, memo, useMemo, useCallback jahan zaroori ho Doctor pehle test karta hai, phir dawai deta hai. Profiler = test. Bina reason ke har jagah memo lagana = bina test ke dawai. "First I identify the unnecessary render using React Profiler, then optimize the actual cause instead of blindly using memoization."
2 Parent re-render hone par child bhi re-render ho raha hai. Parent render + har render par naya object/function reference React.memo + useCallback / useMemo se stable references {} !== {}. Har render par naya object = React ko lagta hai prop badal gaya. memo + stable ref = jodi, akela memo bekaar. "I use React.memo when the child's props haven't changed, and check for new object/function references."
3 API ke baad UI slow ho gayi. Bada data, heavy JS, zyada renders, slow API Network tab + Profiler → bottleneck pakdo → wahi fix karo 4 suspects: API · Network · JS · Render. Network tab se pata chalega API slow hai ya nahi. Profiler se pata chalega render slow hai ya nahi. "I first separate API, network, JavaScript and rendering bottlenecks, then optimize the actual bottleneck."
4 10,000 records ki table slow hai. Bahut saare DOM elements Pagination / virtualization (react-window) / server-side filtering Screen par ek baar mein ~20 rows hi dikhti hain, to 10,000 kyun banani? Jo dikhe, wahi render karo. "For large lists I avoid rendering everything at once and use pagination or virtualization."
🌐 API + useEffect
5 Search mein har keystroke par API call ho rahi hai. Debounce nahi hai Debounce 300–500ms Lift ka darwaza: har aane wale ke liye band-khula nahi hota, sab aa jayein phir chalti hai. User typing ruke, tab API call. "I use debouncing so the API is called after the user stops typing."
6 Search API debounce kaise karoge? Har input par request trigger hoti hai useEffect + setTimeout + cleanup (clearTimeout) 3 steps: Timer lagao → naya letter aaya → purana timer cancel. Cleanup function hi purana timer hatata hai. (Code neeche 👇) "I start a timer on search change and clear the previous timer when the user types again."
7 Mount par API aur dependency change par bhi API chahiye. Galat useEffect dependency useEffect(fn, [dependency]) [] = sirf ek baar · [id] = pehli baar + jab id badle · koi array nahi = har render. Array = "kab chalana hai" ki list. "I use useEffect with the required dependency; it runs initially and when that dependency changes."
8 useEffect infinite loop mein hai. Effect apni hi dependency update kar raha hai / har render par naya object-function Dependency cycle todo, references stable karo, effect restructure karo Effect → setState → re-render → dependency badli → effect phir... 🔁 Kutta apni poonch ke peeche. Ya to dependency hatao, ya reference stable karo. "I check whether the effect updates a dependency or receives a new reference on every render."
9 Old API response latest data ko overwrite kar raha hai. Race condition AbortController / stale-response ignore flag "ab" search kiya, phir "abc". "ab" ka response late aaya aur "abc" ko overwrite kar diya. Purani request cancel karo, sirf latest jeete. "I cancel obsolete requests or ignore stale responses so older data cannot overwrite newer data."
10 API-2 ko API-1 ka response chahiye. Requests ek doosre par depend hain Sequential await. Independent APIs ke liye Promise.all Pehle user ki ID lao, tab uske orders. Chai se pehle paani ubaalna padta hai. Depend nahi karte? To Promise.all se saath mein chalao. "I await the first API, then use its response to call the second. If the calls are independent, I run them in parallel with Promise.all."

🔄 Data Flow: Parent ↔ Child ↔ Sibling
11 Child ko parent ki state update karni hai. Parent ki state child ki nahi hai, wo directly change nahi kar sakta Parent callback / setter ko prop bana ke bhejo Bachcha papa ka wallet khud nahi kholta, papa ko bolta hai "paise do". Callback = papa ko request. State jiski, update bhi wahi karega. "I pass a callback from parent to child, and the child calls it to request the state update."
12 Sibling components ko same data chahiye. State ek sibling ke andar band hai Lift state up: nearest common parent mein le jao Do bhai ek TV remote ke liye lad rahe hain. Remote mummy (parent) ke paas rakho, dono ko wahi se milega. "I move the shared state to their nearest common parent and pass data/callbacks as props."
13 Prop drilling bahut zyada hai. Data aise components se pass ho raha jinko uski zaroorat hi nahi Composition (children) → Context → Redux, zaroorat ke hisaab se Parcel 5 padosiyon ke haath se ghar pahunch raha hai. Direct courier (Context) bhejo. Pehle check karo: kya children pass karke hi kaam ho jayega? "I first check whether the state can be moved or composed; for genuinely shared state I can use Context or Redux."
14 Context ke baad unnecessary re-renders. Ek bada context / provider value har render par naya object Contexts split karo + useMemo se stable value + provider ko sirf zaroori tree par lagao Ek WhatsApp group mein sab kuch post hoga to sabko notification jayegi. Alag groups banao (ThemeContext, UserContext). Value {} har baar naya = sabko ping. "I split unrelated context values and stabilize provider values where appropriate."
15 Local State vs Context vs Redux? Galat state-management tool choose kiya Local → simple shared (Context) → complex global (Redux) Ghar ka fridge → society ka notice board → bank. Ek component = useState. Kam badalne wala shared data (theme, user) = Context. Bada, baar-baar badalne wala app data = Redux. "I prefer local state first, Context for simple shared data, and Redux for large complex application-wide state."
⏳ setState ka behaviour
16 setState() ke baad immediately old value mil rahi hai. Update schedule hota hai, current render ki value same rehti hai Nayi value next render mein padho / functional updater use karo Zomato par order kiya, khana abhi plate mein nahi aaya. setCount(5) ke turant baad count purana hi rahega, next render mein 5 hoga. "State setters schedule an update; they don't immediately change the current render's value."
17 Multiple state updates karne hain. Updates previous state par depend hain, par sab same purani value dekh rahe hain Functional updater: setCount(prev => prev + 1) setCount(count+1) 3 baar = +1 hi hoga (teeno ne 0 dekha). prev => 3 baar = +3, kyunki har update line mein khade hoke pichla result leta hai. "setCount(prev => prev + 1) ensures each update uses the latest previous state."
18 Previous state ke basis par update karna hai. Nayi value purani value par depend karti hai Functional updater Simple rule: "purani value chahiye? → prev =>". Toggle (prev => !prev), counter, list mein add, sab isi se. "Whenever the new state depends on previous state, I use the functional updater."
📝 Forms + Immutability
19 Form ka ek field change → poora form re-render. Saari state ek bade component mein, tree mein bahut upar Form ko chhote components mein todo, state local rakho, heavy fields memoize karo (ya React Hook Form) Ek bulb ke liye poore ghar ka main switch mat dabao. Har field ka apna switch ho. State jitni neeche, re-render utna chhota. "I split the form, keep state close to where it is used, and optimize expensive fields."
20 Nested state update without mutation? Object ko directly mutate kiya, reference same raha, React ko change dikha hi nahi Spread se har level ki copy banao (ya Immer) React sirf naya dabba dekh ke samajhta hai ki kuch badla. Purane dabbe ke andar saaman badla = same dabba = no re-render. Jis level ko badlo, us tak har level spread karo. "I never mutate state directly; I create a new object using the spread operator at every nested level I change, so React detects the new reference."

🧮 useMemo vs useCallback
21 useMemo kab use karoge? Expensive calculation har render par dobara chal rahi hai Expensive result ko useMemo se memoize karo Maths ka bada sawaal ek baar solve karke answer copy mein likh lo. Jab tak numbers (dependencies) na badlein, dobara solve mat karo. Chhoti calculation par mat lagao, uska bhi cost hota hai. "I use useMemo when an expensive calculation doesn't need to run on every render."
22 useCallback kab use karoge? Har render par function ka naya reference ban raha hai Function ko useCallback se memoize karo Akela useCallback koi fayda nahi deta. Iski jodi React.memo child ke saath hai (P1 #2 yaad karo). Ya jab function kisi useEffect ki dependency ho. "I use useCallback when function reference stability matters, especially when passing callbacks to memoized children."
23 useMemo vs useCallback? Dono ka purpose confuse hota hai useMemo → value · useCallback → function Memo = Maal (result), Callback = Call karne wala function. Asal mein useCallback(fn, deps) = useMemo(() => fn, deps). "useMemo memoizes a calculated value, while useCallback memoizes a function reference."
♻️ Custom Hooks
24 Custom Hook kab banaoge? Same stateful logic kai components mein duplicate hai Reusable custom hook (useSomething) Roz ki chai ki recipe ek baar likh lo, sab log follow karein. Normal function mein hooks nahi chal sakte, custom hook mein chal sakte hain. Isliye naam use... se. "I create a custom hook when the same stateful or side-effect logic is reused across components."
25 Multiple components mein same API/loading/error logic hai. Duplicate logic useFetch jaisa custom hook / shared data layer (React Query) Har component mein wahi 3 cheezein: data, loading, error. Isko ek useFetch(url) mein daalo, component bas ek line likhe. (Code neeche 👇) "I extract the common API and state-management logic into a custom hook so components can reuse it."
📌 useRef
26 useRef ka real-project use kya hai? Aisi value chahiye jo renders ke beech bachi rahe, par re-render na karaye DOM reference (focus/scroll) · timer ID · previous value · mutable flag Ref = jeb mein rakhi parchi. Parchi par kuch bhi likho, kisi ko pata nahi chalega (no re-render), par parchi gum nahi hogi. Use: inputRef.current.focus(), timerRef.current = setInterval(...). "useRef is useful for DOM references and mutable values that should persist across renders without causing a re-render."
27 useRef change hone par re-render kyun nahi hota? Ref update state update nahi hai ref.current badalna render trigger nahi karta State = notice board (badla to sab dekhte hain, re-render). Ref = personal diary (badla to kisi ko khabar nahi). React sirf setState par dhyan deta hai. "Changing ref.current doesn't trigger a render because React doesn't treat it as state."
⚖️ Hook Rules + Timing
28 useEffect vs useLayoutEffect? Dono ki timing alag hai useEffect → paint ke baad · useLayoutEffect → browser paint se pehle Diwar paint karni hai. useLayoutEffect = paint se pehle naap-tol karo (tooltip position, element size). useEffect = paint ke baad baaki kaam (API, subscriptions). 95% cases mein useEffect. Layout wala blocking hai, paint ko rok deta hai. "I normally use useEffect for side effects. useLayoutEffect is for cases where I need to measure or synchronously adjust the DOM before the browser paints."
29 Hook ko condition ke andar call kar sakte hain? Hook order change ho sakta hai Hooks hamesha top level par. Condition hook ke andar lagao React hooks ko roll number se pehchanta hai (1st useState, 2nd useEffect...). Kisi din ek student absent (if false) = sabke roll number khisak gaye = galat state mili. No if, no loop, no early return se pehle. "Hooks must be called at the top level so React can preserve the same hook order between renders."
30 Custom hook mein API call + cleanup kaise karoge? Request ko component ke lifecycle ke saath manage karna hai useEffect + cleanup return / AbortController Ghar se niklo to light-pankha band karke niklo. Component unmount ho ya URL badle, to purani request abort, timer clear, subscription hatao. = P1 #9 + #24 ka combo. "I put the API side effect inside useEffect and clean up subscriptions, timers or in-flight requests when necessary."

#25 + #30 · useFetch custom hook (with cleanup)

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    fetch(url, { signal: controller.signal })
      .then(res => res.json())
      .then(setData)
      .catch(err => {
        if (err.name !== 'AbortError') setError(err);
      })
      .finally(() => setLoading(false));
    return () => controller.abort(); // cleanup
  }, [url]);

  return { data, loading, error };
}

// Use: ek line!
const { data, loading, error } = useFetch('/api/users');

⏳ Slow / Failed API
31 API slow hai, UI ko user-friendly kaise rakhoge? Slow network / server Loading state, skeleton, timeout, retry, cached data Restaurant mein khana late ho to waiter pehle starter / paani de deta hai. Skeleton = starter. User ko lage ki kuch ho raha hai. Cached data = kal ka bacha khana, turant dikhao, phir fresh laao. 32 API fail ho gayi. Retry/error/fallback kaise? Network / server error Error state + controlled retry + fallback UI (Error Boundary) ATM se paise nahi nikle to screen blank nahi hoti, "Try again" dikhata hai. Retry controlled ho (2–3 baar, gap badhate hue = exponential backoff), warna server par hamla ho jayega. "I handle loading, success and error states separately and provide retry or fallback behavior where appropriate."
🚦 Request Control
33 Multiple components same API call kar rahe hain. Duplicate requests Shared data layer / cache (React Query, RTK Query) / custom hook Ghar ke 4 log alag-alag same akhbaar mangwa rahe hain. Ek mangao, sab padho. React Query same key wali requests ko ek kar deta hai (dedupe) aur cache rakhta hai. "I avoid duplicate requests by centralizing the data fetching or using a caching/data-fetching layer."
34 Old API response newer response ko overwrite kar raha hai. Race condition Old request abort / stale response ignore = P1 #9. "ab" ka late response "abc" ko overwrite kar deta hai. Sirf latest request ko UI chhoone do. "I cancel obsolete requests or ignore stale responses so only the latest request updates the UI."
35 Component unmount hone ke baad API response aa raha hai. Request abhi bhi chal rahi hai useEffect cleanup + AbortController Page chhod diya, par courier purane pate par aa gaya. Nikalte waqt order cancel karo (cleanup mein abort()). = P3 #30. "I cancel the request during cleanup so an obsolete request doesn't update the component."
40 User button multiple times click kar raha hai, duplicate API requests. Request control nahi hai Loading flag → button disable / guard (if (loading) return) Lift ka button 10 baar dabao, lift ek hi aayegi. Request chal rahi hai? Button band. Payment jaise cases mein backend par idempotency key bhi. "I prevent duplicate submissions by tracking the request state and disabling or guarding the action while the request is in progress."
📚 Bada Data
36 1 lakh records hain. Pagination kaise? Huge data Server-side pagination (?page=2&limit=20) Library se poori library ghar nahi laate, ek baar mein 20 kitaabein. Browser sirf current page ka data maange. Total count server batayega. "I would use server-side pagination instead of loading the complete dataset into the browser."
37 Infinite scroll implement karni hai. Large dataset IntersectionObserver + page / cursor based API Instagram feed. List ke end par ek invisible "chowkidar" div rakho. Jaise hi wo screen par dikhe → next page mangao. Cursor = "is post ke baad wale do". "I would load data incrementally using pagination or cursor-based APIs and trigger the next request near the end of the list."
38 API 10,000 records return kar rahi hai. Huge response + memory / rendering cost Backend filtering / pagination + virtualization 2 problem = 2 fix: network bhaari → backend kam bheje (filter/paginate). DOM bhaari → sirf dikhne wali rows render (virtualization, P1 #4). "I would avoid sending all records to the client and use server-side filtering, pagination and virtualization where needed."
⚡ Optimistic UI
39 Optimistic UI update kab use karoge? User ko response ka wait karna pad raha hai UI turant update → API call → fail ho to rollback Instagram ❤️ like: dil turant laal ho jaata hai, API baad mein. Fail hua to wapas safed. Sirf wahan use karo jahan fail hona rare ho aur galti sasti ho (like, todo). Payment par nahi. "I use optimistic updates when the operation is expected to succeed and immediate UI feedback improves UX; on failure I rollback the change."

What is React? Role of React in Client-Server Architecture & ReactDOM vs React

V. IMP GFG #1, #9

1. React vs Angular (Library vs Framework):

  • Angular is a full Framework: Opinionated structure, provides built-in HTTP client, Form validation, Dependency Injection, and Routing out of the box.

Core Engine

Virtual DOM, Reconciliation Diffing (GFG #16, #128) & React Fiber

Senior Round GFG #16, #128

1. How the Virtual DOM Works:

  1. Direct Real DOM manipulation causes expensive Layout Reflow and Repaint.
  2. React keeps an in-memory Virtual DOM tree. When state changes, a new VDOM tree is created.
  3. Reconciliation: React compares the previous VDOM with the new VDOM using a heuristic O(n) diffing algorithm.
  4. Only the exact changed DOM nodes are batched and updated in the real DOM.

2. React Fiber Architecture:

  • Stack Reconciler (pre-React 16) used synchronous recursive tree traversal, which blocked the main thread on large trees.
  • Fiber Reconciler splits rendering into units of work. It enables Time-Slicing and Cooperative Scheduling: high-priority tasks (typing, clicks) interrupt low-priority tasks (background data render).

React Fragments (GFG #8) & Conditional Rendering Techniques (GFG #10, #47, #48)

GFG #8, #10, #47

1. Why React Fragments (`<>...</>`):

JSX must return a single root element. Wrapping in an extra <div> creates unnecessary DOM nodes, breaking CSS Flexbox/Grid layouts or HTML table structure (e.g. <td> inside a <div> inside a <tr> is invalid HTML). Fragments group elements with zero extra DOM nodes.

// Shorthand Fragment:
return (
  <>
    <Header />
    <Main />
  </>
);

// Explicit Fragment (Required when passing a key in lists!):
{items.map(item => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.description}</dd>
  </React.Fragment>
))}

2. Conditional Rendering Pitfalls with `&&`:

If count is 0, count && <Component /> will render the number 0 on screen because JavaScript evaluates falsy 0 as output! Always use boolean coercion or ternary:

// ❌ Bug: Renders "0" on screen when count is 0
{count && <Badge count={count} />}

// ✅ Safe Fix 1: Boolean check
{count > 0 && <Badge count={count} />}

// ✅ Safe Fix 2: Ternary Operator
{isLoggedIn ? <Dashboard /> : <Login />}

GFG Core

Functional vs Class Components (GFG #4) & React.PureComponent (GFG #131)

GFG #4, #131

1. Functional vs Class Component:

  • Functional: Plain JavaScript function returning JSX. Uses Hooks for state and lifecycles. No this keyword confusion, smaller bundle size.
  • Class: Extends React.Component, requires a render() method, manages state in this.state, uses lifecycle methods.

1. What is a SyntheticEvent?

React wraps native browser events in a cross-browser wrapper called SyntheticEvent. It has the exact same interface as native events (e.stopPropagation(), e.preventDefault()), ensuring consistent behavior across Chrome, Safari, Firefox, and Edge.

2. Event Delegation in React 17+:

Hooks Deep Dive

Lazy Initialization (GFG #88) & useEffect Omitted Dependencies Bug (GFG #86, #111)

V. IMP GFG #86, #88, #111

1. Lazy State Initialization in `useState`:

If initial state requires an expensive computation (e.g. reading localStorage or parsing large JSON), passing it directly executes the computation on every single re-render! Pass a function instead so it executes only once on mount:

// ❌ Slow: localStorage read on EVERY re-render
const [theme, setTheme] = useState(localStorage.getItem('theme'));

// ✅ Fast: Evaluated strictly ONCE on mount (Lazy initialization)
const [theme, setTheme] = useState(() => {
  return localStorage.getItem('theme') || 'dark';
});

2. What happens if you omit dependencies in useEffect? (GFG #86):

  • The effect creates a Stale Closure, referencing outdated state or prop values from the initial render.
  • Network calls won't refetch when parameters change.
  • If you omit the array completely useEffect(fn), the effect runs after every render, risking infinite loops if state is updated inside!

GFG #110, #115

useRef vs createRef (GFG #110) & useMemo vs useCallback (GFG #81, #115)

GFG #110, #115

1. useRef vs createRef:

  • createRef(): Always creates a brand new ref object { current: null } on every render. Used in Class components.
  • useRef(): Persists the exact same ref object across all renders in functional components. Updating ref.current does not trigger a re-render.

2. useMemo vs useCallback:

  • useMemo: Caches the calculated value/result of an expensive function.
  • useCallback: Caches the function definition/reference itself to avoid breaking child React.memo shallow comparison.
// useMemo: Caches the result of sorting 10k items
const sortedList = useMemo(() => {
  return items.slice().sort((a, b) => b.score - a.score);
}, [items]);

// useCallback: Caches function reference
const handleClick = useCallback((id) => {
  dispatch({ type: 'SELECT', payload: id });
}, [dispatch]);
