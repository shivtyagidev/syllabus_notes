01

Values — Data Types, Primitive/Object, Coercion

JavaScript mein sab kuch ek value hai. Pehle yeh samjho ki value kitne type ki hoti hai.

Big picture: JS dynamically typed hai. Type value ka hota hai, variable ka nahi. Isliye ek hi variable mein pehle number aur baad mein string rakh sakte ho. Isi flexibility ki wajah se coercion wale bugs aate hain.

1.1 Data Types (8 types)

What7 primitive: string, number, bigint, boolean, undefined, null, symbol. 1 non-primitive: object (arrays, functions, dates sab objects hain).
Why aayaEngine ko pata hona chahiye ki memory kaise allocate kare aur kaunse operations allowed hain. bigint isliye aaya kyunki number 2^53 se bade integers safely nahi rakh sakta. symbol unique keys ke liye aaya.
WhenHar jagah. Input validate karte waqt, API response check karte waqt aur debugging mein typeof use hota hai.
HowType check karne ke liye typeof use karo. Array ke liye Array.isArray() aur null ke liye === null.
typeof "hi"        // "string"
typeof 42          // "number"
typeof 10n         // "bigint"
typeof undefined   // "undefined"
typeof null        // "object"   ← JS ka purana bug
typeof []          // "object"   → Array.isArray([]) use karo
typeof function(){} // "function" (function bhi object hai)
typeof NaN         // "number"   ← NaN bhi number hai
JS mein 7 primitive types aur 1 object type hai. Primitives immutable hote hain aur value se copy hote hain. Objects mutable hote hain aur reference se pass hote hain.
typeof null === "object" ek historical bug hai. NaN !== NaN hota hai, isliye check ke liye Number.isNaN() use karo.

1.2 Primitive vs Object (Reference)

WhatPrimitive ki value copy hoti hai. Object ka reference (address) copy hota hai.
Why aayaBade objects ko har baar copy karna costly hota. Isliye engine sirf pointer share karta hai. Chhoti primitive values seedha copy ho jaati hain.
WhenFunction mein object pass karna, React state update karna, ya copy banana ho, tab yeh samajhna zaroori hai.
HowPrimitives zyada tar stack par rehte hain aur objects heap par. Variable ke paas sirf heap ka address hota hai.
let a = 10; let b = a; b = 20;
console.log(a);           // 10  → value copy

let o1 = { x: 1 }; let o2 = o1; o2.x = 99;
console.log(o1.x);        // 99  → same reference

console.log({} === {});   // false → alag address
Primitives value se compare aur copy hote hain. Objects reference se, isliye do same-looking objects bhi === mein false dete hain.

1.3 Type Coercion (Implicit vs Explicit)

WhatEk type ko doosre type mein convert karna. Explicit matlab tum khud karte ho (Number("5")). Implicit matlab JS khud kar deta hai ("5" * 2).
Why aayaJS browser ke liye bani thi taaki galat input par bhi page crash na ho. Isliye yeh values ko "adjust" kar leti hai.
WhenForm inputs hamesha string hote hain, isliye unhe explicitly convert karo. Implicit coercion par depend mat karo.
How+ mein ek side string ho to string concat hota hai. - * / hamesha number mein convert karte hain. if() ke andar value boolean ban jaati hai.
"5" + 2      // "52"
"5" - 2      // 3
true + 1     // 2
[] + []      // ""
[] + {}      // "[object Object]"
null + 1     // 1     (null → 0)
undefined + 1 // NaN  (undefined → NaN)

// Falsy values (sirf 8): false, 0, -0, 0n, "", null, undefined, NaN
// Baaki sab truthy hai: "0", "false", [], {} bhi
Coercion JS ka automatic type conversion hai. + string ko prefer karta hai aur baaki arithmetic operators number ko. Production code mein main explicit conversion aur === use karta hoon.
[] aur {} truthy hain. if ([]) chalega. Empty array check karne ke liye arr.length === 0 likho.

Interview Q&A

null vs undefined mein kya farak hai?
undefined ka matlab hai value abhi assign nahi hui, yeh JS khud set karta hai. null ka matlab hai "yahan jaan-boojh kar koi value nahi hai", yeh developer set karta hai. null == undefined true hai, null === undefined false hai.
0.1 + 0.2 === 0.3 false kyu hai?
JS numbers IEEE-754 floating point mein store hote hain aur 0.1 binary mein exact represent nahi hota. Result 0.30000000000000004 aata hai. Fix: Math.abs(a-b) < Number.EPSILON. Paison ke liye paise ko integer (cents) mein store karo.
Primitive par method kaise chalta hai? ("hi".toUpperCase())
Auto-boxing hota hai. JS temporarily ek wrapper object (new String("hi")) banata hai, method call karta hai, phir us wrapper ko discard kar deta hai.

02

Variables — var / let / const, TDZ

Value ko naam dena hai taaki baad mein use kar sakein.

Big picture: ES5 mein sirf var tha, jo function-scoped tha aur hoisting ke saath undefined deta tha. Isse bahut bugs aate the. ES6 (2015) mein let/const aaye, jo block-scoped hain aur jinmein TDZ hai.

WhatTeeno keywords variable declare karne ke liye hain, bas scope aur rules alag hain.
Why aayavar block ko ignore karta hai aur loop mein leak ho jaata hai. let/const is problem ko fix karne aaye, taaki code predictable rahe.
WhenDefault const rakho. Value badalni ho to let. Naye code mein var mat likho.
Howconst ka binding fix hota hai, value nahi. Const object ke andar ki properties badal sakte ho.

var function-scoped hai, let aur const block-scoped hain. const re-assignment rokta hai, mutation nahi. Poora object freeze karna ho to Object.freeze use karo.

2.2 TDZ (Temporal Dead Zone)

WhatBlock shuru hone se lekar let/const declaration line tak ka area. Is area mein variable exist karta hai par access karne par ReferenceError aata hai.
Why aayavar declaration se pehle chupchap undefined de deta tha, jisse silent bugs bante the. TDZ is galti ko turant error bana deta hai.
WhenDeclaration se pehle variable use karoge to yeh error dikhega. Interviews mein output questions mein bahut aata hai.
HowCreation phase mein let/const ko memory milti hai par uninitialized state mein. Declaration line execute hone par hi value set hoti hai.
console.log(a);  // undefined
var a = 1;

console.log(b);  // ReferenceError: Cannot access 'b' before initialization
let b = 2;
let/const bhi hoist hote hain, lekin initialize nahi hote. Declaration tak ka area TDZ kehlata hai. Wahan access karne par ReferenceError aata hai.

Interview Q&A

Kya let/const hoist hote hain?
Haan, hote hain. Engine ko unka pata creation phase mein hi chal jaata hai. Farak yeh hai ki var undefined se initialize hota hai, jabki let/const TDZ mein rehte hain.
const array mein push kyu ho jaata hai?
const sirf variable ka binding lock karta hai, matlab variable doosre array ko point nahi kar sakta. Array ke andar ka data mutable hai.

03

Scope — Global, Function, Block, Lexical, Module

Variable code ke kis hisse se accessible hai?

Big picture: Scope = variable ki visibility. Scope isliye hai taaki naam aapas mein na takraayein (naming collision) aur data ek controlled area mein rahe (encapsulation).

3.1 Global, Function, Block Scope

WhatGlobal: poore program mein accessible. Function: sirf function ke andar. Block: sirf { } ke andar, aur sirf let/const ke liye.
Why aayaSab kuch global hota to har library ek-doosre ke variables overwrite kar deti. Scope isolation deta hai.
WhenVariable ko hamesha sabse chhote scope mein rakho jahan uski zaroorat hai. Globals kam se kam rakho.
HowHar function call aur block ek naya scope banata hai. Andar wala scope bahar wale ke variables dekh sakta hai, bahar wala andar ke nahi.
let g = "global";
function fn() {
  let f = "function";
  if (true) { let b = "block"; console.log(g, f, b); }  // sab accessible
  console.log(b);   // ReferenceError
}

3.2 Lexical Scope

WhatScope is baat se decide hota hai ki code kahan likha gaya hai, is baat se nahi ki function kahan se call hua.
Why aayaIsse code predictable rehta hai. Code padh kar hi pata chal jaata hai ki kaunsa variable use hoga. Closures isi par based hain.
WhenNested functions aur closures samajhne ke liye yeh zaroori hai.
HowFunction banate waqt JS uske parent scope ka reference save kar leta hai ([[Environment]]).
let x = "outer";
function a() { console.log(x); }
function b() { let x = "inner"; a(); }
b();   // "outer" → a() jahan LIKHA hai wahan ka x use hota hai
JS lexical (static) scoping follow karta hai. Function ka scope define hone ki jagah se decide hota hai, call hone ki jagah se nahi.

3.3 Module Scope

WhatES module (ya CommonJS file) ke top-level variables sirf usi file mein visible hote hain.
Why aayaPehle saari <script> files ek hi global scope share karti thi, jisse collisions hote the. Modules ne har file ko apna private scope diya.
WhenAaj ke saare React/Node projects mein yahi default hai.
HowKuch share karna ho to export karo, use karna ho to import. Baaki sab private rehta hai.

Interview Q&A

Lexical scope vs dynamic scope?
Lexical scope mein function kahan define hua, woh matter karta hai. JS isi ko follow karta hai. Dynamic scope mein function kahan se call hua, woh matter karta hai. JS mein sirf this dynamic jaisa behave karta hai.
Global scope pollution kaise avoid karein?
Modules use karo, IIFE use karo, aur let/const use karo (var nahi). Browser globals ko ek namespace object mein rakho.

04

Hoisting + Scope Chain

Code chalne se pehle JS declarations ke saath kya karta hai?

4.1 Hoisting

WhatCode execute hone se pehle declarations ko memory mil jaati hai. Isse aisa lagta hai jaise declarations "upar" chali gayi hon.
Why aayaJS pehle code ko scan karta hai (creation phase). Isi wajah se function ko uski definition se pehle bhi call kar sakte ho, aur mutually recursive functions kaam karte hain.
WhenOutput questions mein, aur jab declaration se pehle use karne par koi bug aaye.
HowCode physically move nahi hota. Sirf memory allocation pehle ho jaata hai.
DeclarationHoisted?Initial value
var✅undefined
let / const✅TDZ (uninitialized)
Function declaration✅Poora function
Function expression / arrowSirf variable hoist hota hai (var ya let ke rules se)Function nahi

greet();                 // "hi" ✅ function declaration
function greet(){ console.log("hi"); }

Hoisting mein creation phase ke dauraan declarations ko memory milti hai. var ko undefined milta hai, function declaration ko poori body, aur let/const/class TDZ mein rehte hain.

4.2 Scope Chain (Local → Outer → Global)

WhatKoi variable use hone par JS usse pehle current scope mein dhoondhta hai, phir parent scope mein, aur aise hi global tak jaata hai. Wahan bhi na mile to ReferenceError.
Why aayaNested functions ko bahar ka data chahiye hota hai, aur har baar pass karna practical nahi hai.
WhenNested functions, closures, aur shadowing samajhne mein.
HowHar execution context ke paas ek "outer environment" ka reference hota hai. Yeh references aapas mein jud kar ek chain banate hain.
let a = 1;
function outer() {
  let b = 2;
  function inner() { let c = 3; console.log(a + b + c); }  // 6
  inner();
}
outer();

// Shadowing: andar wala same naam bahar wale ko chhupa deta hai
let n = 1; { let n = 2; console.log(n); }  // 2
Scope chain lexical environments ki ek linked list hai. Lookup andar se bahar ki taraf hota hai, ulta kabhi nahi.

Interview Q&A

Function declaration aur same naam ka var, dono ho to kya hoga?
Creation phase mein function declaration ko priority milti hai. Execution phase mein var ka assignment use overwrite kar deta hai.
Illegal shadowing kya hai?
Jab block ke andar var se aisa naam declare karo jo bahar let se already declared hai, to SyntaxError aata hai, kyunki var block ko cross karke function scope tak chala jaata hai.

05

Execution Model — Execution Context, Phases, Call Stack

Hoisting, scope aur closure teeno isi ek model se samajh aate hain.

5.1 Execution Context (EC)

WhatWoh environment jisme code chalta hai. Isme 3 cheezein hoti hain: variables (memory), scope chain, aur this.
Why aayaEngine ko track karna hota hai ki abhi kaunsa code chal raha hai, uske variables kaunse hain, aur this kya hai.
WhenProgram start hone par Global EC banta hai. Har function call par ek naya Function EC banta hai.
HowHar EC do phases mein chalta hai: Creation aur phir Execution.

5.2 Creation Phase vs Execution Phase

Creation (Memory) PhaseExecution (Code) Phase
var ko undefined milta hai, functions ko poori body, let/const TDZ mein jaate hainCode line-by-line chalta hai, values assign hoti hain
Scope chain set hoti hai, this decide hota haiFunction call par naya EC banta hai aur stack par push hota hai
Creation phase mein memory allocate hoti hai (isi se hoisting hoti hai). Execution phase mein code line by line chalta hai. Hoisting creation phase ka side-effect hai.

5.3 Call Stack

WhatEk LIFO stack jo track karta hai ki abhi kaunsa function chal raha hai.
Why aayaJS single-threaded hai, ek time par ek hi kaam karta hai. Stack order maintain karta hai ki function khatam hone ke baad control kahan wapas jaayega.
WhenError stack trace padhne mein, recursion mein, aur event loop samajhne mein.
HowFunction call hone par push, return hone par pop. Stack bahut bhar jaaye to RangeError: Maximum call stack size exceeded aata hai.
function a(){ b(); }
function b(){ c(); }
function c(){ console.trace(); }
a();
// Stack: [Global] → [a] → [b] → [c]   (c pehle pop hoga)

function inf(){ inf(); } inf();   // RangeError: stack overflow
Call stack execution contexts ka LIFO stack hai. JS single-threaded hai, isliye ek hi call stack hota hai. Stack khaali ho tabhi event loop async callbacks andar daalta hai.

Interview Q&A

JS single-threaded hai to async kaise hota hai?
JS engine single-threaded hai, par runtime (browser ya Node) ke paas Web APIs/libuv hote hain. Timers, network aur I/O wahan chalte hain. Kaam poora hone par callback queue mein aata hai, aur event loop stack khaali hone par use andar daalta hai. (Detail: section 16)

Logic ko reusable unit mein pack karna.

6.1 Declaration vs Expression vs Arrow

Why arrow aayaCallbacks ke andar this kho jaata tha, aur logon ko var self = this ya .bind(this) likhna padta tha. Arrow function parent ka this use karta hai. Syntax bhi chhota hai.
WhenArrow: callbacks, array methods, React handlers. Normal function: object methods, constructors, aur jab arguments chahiye.
Arrow functions ka apna this, arguments aur prototype nahi hota, aur unhe new se call nahi kar sakte. Isliye yeh callbacks ke liye best hain, par object methods ke liye nahi.

6.2 First-Class Functions

WhatFunctions ko bhi value ki tarah treat kiya jaata hai. Unhe variable mein store kar sakte ho, argument mein pass kar sakte ho, aur return kar sakte ho.
Why aayaIsi feature se callbacks, HOF, closures aur functional programming possible hote hain.
WhenEvent handlers, map/filter, middleware, aur Promise .then mein.
HowFunction internally ek callable object hai. Uske paas properties bhi ho sakti hain, jaise fn.name aur fn.length.

6.3 Callback & Higher-Order Function (HOF)

WhatCallback = woh function jo doosre function ko argument mein diya jaata hai, taaki woh use baad mein call kare. HOF = woh function jo function leta hai ya function return karta hai.
Why aayaBehaviour ko customize karne ke liye. Loop ka logic ek hi baar likho, aur "kya karna hai" callback se bata do. Async kaam ke "baad" kya chalana hai, woh bhi callback se batate hain.
Whenmap, filter, reduce, setTimeout, addEventListener, aur Express middleware mein.
// HOF: function return kar raha hai
const multiplier = (n) => (x) => x * n;
const double = multiplier(2);
double(5);                        // 10

// Callback
[1,2,3].map(x => x * 2);          // [2,4,6]  → map HOF hai, x=>x*2 callback hai
Callback woh function hai jo argument mein pass hota hai. HOF woh function hai jo function leta ya return karta hai. Dono first-class functions ki wajah se possible hain.

6.4 IIFE, Default Params, Pure Function

IIFE(function(){ ... })() matlab function define hote hi turant call ho jaata hai. Modules aane se pehle private scope banane ke liye use hota tha.
Defaultfunction f(a = 10){}. Default value tabhi lagti hai jab argument undefined ho, null par nahi lagti.
PureSame input par hamesha same output, aur koi side effect nahi. Aise functions test aur cache (memoize) karna aasaan hota hai. React reducers pure hone chahiye.

Interview Q&A

Object method ke liye arrow kyu nahi use karna chahiye?
Arrow function ka apna this nahi hota, woh bahar wala (module/global) this le leta hai. Isliye obj.method() mein this.name undefined aayega.
Function ki length property kya batati hai?
Kitne parameters declare hue hain, default value aur rest parameter se pehle tak ke. Currying implement karte waqt yeh kaam aata hai.

07

Closure — Lexical Environment, Private State, Factory

Interview ka #1 topic. Scope aur Execution Context ka combination.

One line: Closure = function + uska lexical environment. Outer function return ho jaaye tab bhi inner function outer ke variables yaad rakhta hai.

7.1 Closure kya hai

WhatJab inner function apne outer function ke variables ko outer function khatam hone ke baad bhi access karta hai.
Why aayaJS mein functions first-class hain aur lexical scoping hai. Jab function ko return karke kahin aur chalaya jaata hai, use apna original data yaad rehna chahiye. Closure isi ki guarantee deta hai. JS mein private variables banane ka pehla tareeka bhi yahi tha.
WhenData hiding, factory functions, memoization, debounce/throttle, event handlers, aur React hooks mein.
HowFunction banne par woh parent environment ka reference ([[Environment]]) save kar leta hai. Jab tak inner function reachable hai, woh environment garbage collect nahi hota.
function counter() {
  let count = 0;                    // private state
  return {
    inc: () => ++count,
    get: () => count
  };
}
const c = counter();
c.inc(); c.inc();
c.get();        // 2
c.count;        // undefined → bahar se direct access nahi hota
Closure ek function aur uske lexical environment ka bundle hai. Isse inner function outer ke variables ko baad mein bhi access kar sakta hai. Main ise private state, factories aur memoization ke liye use karta hoon.

7.2 Factory Function (Closure se)

WhatAisa function jo configured naye functions ya objects return karta hai, aur har ek ka apna alag closure hota hai.
WhenEk hi logic ke alag-alag configured versions chahiye hon, jaise loggers, API clients, validators.
const createLogger = (prefix) => (msg) => console.log(`[${prefix}] ${msg}`);
const authLog = createLogger("AUTH");
authLog("login ok");      // [AUTH] login ok

7.3 Classic Loop + setTimeout Problem

WhatYeh interview ka sabse common closure output question hai.
Why hotavar function-scoped hai, isliye teeno callbacks ek hi i share karte hain. Jab tak callbacks chalte hain, loop khatam ho chuka hota hai aur i = 3 hai. let har iteration mein naya binding banata hai.
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));
// 3 3 3

for (let i = 0; i < 3; i++) setTimeout(() => console.log(i));
// 0 1 2

// var ke saath fix: IIFE se har baar naya scope
for (var i = 0; i < 3; i++) ((j) => setTimeout(() => console.log(j)))(i);
Closures variables ka reference yaad rakhte hain, value ki copy nahi. Isliye variable baad mein badle to closure ko nayi value dikhti hai.

7.4 Closure ka nuksaan

WhatJab tak closure zinda hai, uske captured variables memory mein rehte hain. Agar koi bada object capture hua hai aur listener ya timer kabhi remove nahi hua, to memory leak hota hai.
FixListeners remove karo, timers clear karo, aur closure mein sirf zaroori data capture karo.

Interview Q&A

once() function likho (sirf ek baar chale)
function once(fn) {
  let done = false, result;
  return function (...args) {
    if (!done) { done = true; result = fn.apply(this, args); }
    return result;
  };
}
React mein closure ka stale state problem kya hai?
useEffect ya setInterval ka callback purane render ki state capture kar leta hai (stale closure). Fix: dependency array sahi do, ya functional update setCount(c => c + 1) use karo, ya useRef use karo.

08

this — Call-site, Method, Arrow, call/apply/bind

Scope lexical hai, lekin this dynamic hai. Yeh function kaise call hua, us par depend karta hai.

Why aaya: Ek hi function ko alag-alag objects ke saath reuse karne ke liye. Method ko pata hona chahiye ki woh "kis object" par chal raha hai. Isliye this call time par decide hota hai.

8.1 this ke 4 Rules (priority order)

Interview Q&A

function debounce(fn, delay) {
  let t;
  return function (...args) {
    clearTimeout(t);
    t = setTimeout(() => fn.apply(this, args), delay);
  };
}

function throttle(fn, limit) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= limit) { last = now; fn.apply(this, args); }
  };
}

function curry(fn) {
  return function curried(...args) {
    return args.length >= fn.length
      ? fn.apply(this, args)
      : (...next) => curried.apply(this, [...args, ...next]);
  };
}
const add = curry((a, b, c) => a + b + c);

22.3 Memoization

WhatFunction ke result ko input ke hisaab se cache karna. Same input dobara aaye to calculate kiye bina cached result de do.
Why aayaExpensive calculations ko baar-baar karna waste hai. Time ke badle memory kharch karte hain.
WhenSirf pure functions par. Examples: recursive fibonacci, heavy derived data, React useMemo/React.memo, reselect.
function memoize(fn) {
  const cache = new Map();
  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const res = fn.apply(this, args);
    cache.set(key, res);
    return res;
  };
}
const fib = memoize(n => n < 2 ? n : fib(n - 1) + fib(n - 2));   // O(2^n) → O(n)
Memoization closure ke andar ek cache rakhta hai. Yeh sirf pure functions ke liye safe hai. Cache unbounded ho sakta hai, isliye production mein main LRU ya size limit lagata hoon.

DevTools Memory tab mein heap snapshots compare karo. Detached DOM nodes, bina remove kiye listeners, bina clear kiye intervals, bina unsubscribe kiye observables, aur global caches check karo. Component unmount par cleanup karo.
Node API ek endpoint par poora server slow kar rahi hai
Wahan shayad sync CPU-heavy kaam hai (bade JSON par loop, sync crypto, fs.readFileSync) jo event loop ko block kar raha hai. Fix: async APIs use karo, worker_threads ya job queue use karo, streaming use karo, aur DB mein pagination/indexes lagao.

🔐 Security Scenarios

XSS kya hai aur kaise rokoge?
Attacker ki script tumhare page mein chal jaati hai. Aksar user input ko innerHTML mein daalne se hota hai. Fix: textContent use karo, input sanitize karo (DOMPurify), CSP header lagao, aur tokens ke liye HttpOnly cookies use karo. React by default escape karta hai, lekin dangerouslySetInnerHTML se bacho.
CSRF kya hai?
Doosri site user ki logged-in cookie ka use karke unki taraf se request bhej deti hai. Fix: SameSite cookies, CSRF tokens, aur Origin header check karna.
eval / prototype pollution / JWT storage
eval aur new Function user input par kabhi mat chalao. Deep merge karte waqt __proto__ keys block karo. JWT ko localStorage mein rakhoge to XSS se chori ho sakta hai. HttpOnly cookie zyada safe hai. Secrets kabhi frontend bundle mein mat rakho.

🏗️ Real Project Scenarios

"Apne project mein closure / Promise.all / debounce kahan use kiya?" — answer kaise do?
STAR format use karo: Situation (search page slow tha), Task (API calls kam karni thi), Action (300ms debounce aur AbortController lagaya), Result (API calls ~80% kam hui aur stale results wala bug khatam). Concept ka naam, wajah aur measurable result, teeno batao.
Payment button par double click se 2 orders ban gaye
Frontend: click hote hi button disable karo, ya throttle/once lagao. Backend (asli fix): idempotency key use karo, taaki same key wali request dobara process na ho. DB par unique constraint bhi lagao.
Token expire ho gaya aur 5 parallel requests 401 de rahi hain
Ek hi refresh call chalao. Saari failed requests ek shared refresh promise ka wait karein (axios interceptor mein), phir naye token ke saath retry karein. Refresh bhi fail ho to user ko logout karo.
Final tip: Har answer is flow mein do: What (1 line definition) → Why (kaunsi problem solve karta hai) → How (chhota example ya internal kaam) → Where (apne project mein kahan use kiya) → Trap (ek edge case). Isse interviewer ko lagta hai ki concept sach mein samajh aaya hai, sirf yaad nahi kiya.
