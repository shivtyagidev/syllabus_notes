01

Basics

What is Nginx V.IMP

4 roles: web server (static files), reverse proxy (forward to backend), load balancer (traffic split), SSL termination / cache.

Real useNode app port 3000 ke aage Nginx laga do — users 80/443 pe aate hain, andar se Node ko proxy hota hai.

Architecture — Master/Worker V.IMP

Master = config read + workers manage (kabhi request handle nahi karta). Workers = single-threaded but event-driven/non-blocking (epoll/kqueue) → 1000s connections/worker.

Interview lineIsi wajah se Nginx C10k problem (10k concurrent) kam memory mein solve karta hai — thread-per-request nahi hai.

Nginx vs Apache V.IMP

NginxApache
ModelEvent-driven asyncProcess/thread per connection
ConcurrencyHigh, low memoryMemory heavy at scale
Dynamic contentForwards to Node/PHP-FPMmod_php built-in
.htaccessNot supportedSupported

Commands

nginx -tSyntax test — hamesha reload se pehle
nginx -s reloadZero-downtime config reload
nginx -s quitGraceful stop (finish in-flight requests)
nginx -s stopFast/immediate stop

Config Structure & Hierarchy V.IMP

events { worker_connections 1024; }
http {
  include mime.types;
  server {
    listen 80; server_name example.com;
    root /var/www/html; index index.html;
    location / { try_files $uri $uri/ =404; }
    location /api/ { proxy_pass http://localhost:3000; }
  }
}
  • events{} — connection settings, once at top.
  • http{} — HTTP settings + one/more server{}.
  • server{} — one virtual host (domain/port).
  • location{} — rules per URL path.
  • listen, server_name, root, index, include — directive basics.
Interview gotchaSettings upar se neeche inherit hoti hain; priority: location > server > http > main. http{} mein gzip on; likha toh sab servers ko milega, jab tak override na ho.
02

Reverse Proxy & Backend

Reverse Proxy Flow V.IMP

Client → Nginx (public, port 80/443) → Backend (Node, port 3000, sirf internal). Client ko backend ka pata hi nahi chalta.

Real projectReact frontend root se static serve; fetch('/api/products') → Nginx /api/ match → proxy_pass http://localhost:3000/ → Express route → Mongo → response wapas Nginx se browser tak. Security: port 3000 firewall se sirf localhost accessible.

proxy_pass — trailing slash V.IMP

Config/api/users →
proxy_pass http://x:3000/;/users (prefix strip)
proxy_pass http://x:3000;/api/users (as-is)
Common bugTrailing / hai ya nahi — isi se 404 aata hai real projects mein.

proxy_set_header V.IMP

proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
Real useBina X-Real-IP ke, backend ko sabka IP 127.0.0.1 dikhega → rate-limiting/IP-ban ek attacker block karega toh sab users block ho jaayenge.

Proxy Timeouts

proxy_connect_timeoutTCP connect banane ka max time
proxy_send_timeoutRequest bhejne ka max time
proxy_read_timeoutResponse wapas aane ka max time (most important)
Real problemHeavy report route (90s) default 60s timeout se pehle hi 504 de deta hai. Fix: poore server ka timeout mat badhao — sirf us specific location (jyada specific path) ke liye alag proxy_read_timeout do.
03

SSL / HTTPS

HTTP vs HTTPS V.IMP

HTTP = plain text, port 80, "Not Secure". HTTPS = TLS-encrypted, port 443, padlock, SEO boost.

Real scenarioCafe wifi pe login: HTTP → attacker seedha password padh le; HTTPS → sirf encrypted bytes dikhein.

TLS Handshake

1. Client hello (HTTPS chahiye)
2. Server cert bhejta hai (public key)
3. Client CA se verify karta hai
4. Shared session key agree hoti hai
5. Data usi key se encrypt/decrypt

Certificates

CA issue karti hai (Let's Encrypt). 2 files chahiye: cert (.crt/.pem, public) + private key (.key, secret).

Types: DV (domain only, free) → OV (org verified) → EV (banks, deep verification).

Nginx HTTPS Config V.IMP

server {
  listen 443 ssl;
  server_name myshop.com;
  ssl_certificate     .../fullchain.pem;
  ssl_certificate_key .../privkey.pem;
}
# HTTP → HTTPS redirect
server {
  listen 80; server_name myshop.com;
  return 301 https://$host$request_uri;
}

Let's Encrypt + Certbot V.IMP

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d myshop.com -d www.myshop.com

Ek command mein: cert issue + Nginx config + redirect, sab automate, free.

Renewal

Certs sirf 90 din valid. Certbot khud cron/systemd timer laga deta hai — din mein 2 baar check, expiry se 30 din pehle auto-renew.

Interview Q"Site achanak HTTPS error de rahi hai, sabse pehle kya check karoge?" → certbot certificates se expiry date.
04

Load Balancing

upstream block V.IMP

upstream backend_servers {
  server localhost:3001;
  server localhost:3002;
  server localhost:3003;
}
server { location / { proxy_pass http://backend_servers; } }
Real usePM2 cluster mode ya multiple Docker containers ko ek upstream group mein daalte hain.

Algorithms

TypeKab use
Round Robin (default)Sab servers equal capacity
weight=NEk server zyada powerful
least_connProcessing time vary karta ho
ip_hashSession local memory mein (sticky needed)
GotchaSession server-memory mein ho aur ip_hash na lagao → user baar-baar login maanga jaayega (dusre server pe session missing). Better fix: Redis shared session.

Backend Failure Handling V.IMP

upstream backend_servers {
  server localhost:3001 max_fails=3 fail_timeout=30s;
  server localhost:3002 max_fails=3 fail_timeout=30s;
  server localhost:3003 backup;
}

max_fails/fail_timeout = crashed server ko temporarily skip; backup = sab down ho tabhi use.

05

Static Files

root vs alias V.IMP

rootalias
Rulepath appendpath replace
Exampleroot /var/www; /images/cat.png → /var/www/images/cat.pngalias /var/www/pics/; /images/cat.png → /var/www/pics/cat.png
Gotchaalias mein trailing / bhoolna = 404.

try_files & SPA fallback V.IMP

location / { try_files $uri $uri/ /index.html; }

Order: exact file → folder → fallback. SPA routing (/about) client-side hai; bina fallback ke refresh pe 404.

Caching + hashed filenames

location ~* \.(js|css|png|jpg|svg|woff2)$ {
  expires 30d;
  add_header Cache-Control "public, immutable";
}
Problem → FixFile update ho jaaye tab bhi browser 30 din purana cached JS deta rehta — build tools filename mein content-hash daalte hain (app.a3f9e7.js) taaki naya build = naya naam = purani cache kabhi reuse na ho.
06

Performance

Workers & Connections

worker_processes auto;
events { worker_connections 1024; }
# max clients ≈ processes × connections

Keepalive

keepalive_timeout 65;   # client↔Nginx
upstream x { keepalive 32; }  # Nginx↔backend

TCP handshake baar-baar avoid — connection reuse.

Buffering vs Gzip

proxy_buffering — Nginx response ko buffer karke backend ko jaldi free karta hai (streaming mein off).

gzip on; — response compress (200KB → ~50KB).

proxy_cache V.IMP

proxy_cache_path /var/cache/nginx keys_zone=my_cache:10m;
location /api/products {
  proxy_cache my_cache;
  proxy_cache_valid 200 10m;
}

Same request baar-baar DB tak na jaaye — DB load drastically kam.

client_max_body_size V.IMP

http { client_max_body_size 20M; }
GotchaDefault sirf 1MB — set na kiya toh file upload pe seedha 413, Node tak pahunchti hi nahi.

Timeouts = graceful failure

Bina timeout ke crashed backend Nginx ke saare workers busy kar deta hai → poori site down lagti hai. Timeout se turant error, resources free.

07

Security

Rate Limiting V.IMP

limit_req_zone $binary_remote_addr zone=mylimit:10m rate=5r/s;
location /api/login { limit_req zone=mylimit burst=10 nodelay; }

Brute-force login attempts rokta hai — 429 after limit.

IP Blocking & Access Control

location /admin/ { allow 203.0.113.10; deny all; }
location ~ /\.(env|git) { deny all; }

.env block na karo toh secrets public expose ho sakte hain.

Security Headers

add_header X-Frame-Options "SAMEORIGIN";
add_header X-Content-Type-Options "nosniff";
add_header Strict-Transport-Security "max-age=31536000";
add_header Content-Security-Policy "default-src 'self'";

Clickjacking / MIME-sniffing / forced-HTTPS protection.

CORS & SSL Hardening

add_header Access-Control-Allow-Origin "https://myshop.com";
ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers HIGH:!aNULL:!MD5;

Alag-domain frontend/backend ke liye CORS zaroori; purane TLS band karo warna downgrade attack.

DDoS Basics

limit_req_zone $binary_remote_addr zone=req_limit:10m rate=10r/s;
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;
server { limit_req zone=req_limit burst=20; limit_conn conn_limit 20; }

Rate limit + conn limit + timeouts = basic layer; bade DDoS ke liye Cloudflare/AWS Shield chahiye.

08

Logs & Troubleshooting

Access vs Error Log

access_log = "kya hua" (IP, URL, status). error_log = "kyun fail hua" — site down pe sabse pehle yahi dekho.

Status Codes V.IMP

CodeMatlabWajah
403Forbiddendeny all; ya permission issue
404Not foundGalat URL / root path / try_files missing
413Payload too largeclient_max_body_size se badi file
502Bad gatewayBackend down/crashed
504Gateway timeoutBackend slow/hung — timeout cross
Interview line502 = backend respond hi nahi kar raha (restart karo); 504 = respond kar raha but slow (optimize/timeout badhao).

Troubleshooting Order V.IMP

sudo nginx -t                          # 1. syntax check
sudo tail -f /var/log/nginx/error.log  # 2. live error
sudo systemctl status nginx            # 3. Nginx chal raha hai?
curl http://localhost:3000             # 4. backend reachable?
sudo systemctl reload nginx            # 5. reload (restart nahi)
09

Production

PM2 + Nginx

pm2 start server.js -i max --name myshop-api
pm2 startup && pm2 save

Crash pe auto-restart; cluster mode = multiple instances, Nginx unke beech load balance.

EC2 Deployment

Common mistakeNginx config sab sahi, lekin EC2 Security Group mein port 80/443 inbound allow nahi — site bahar se open hi nahi hoti.

Zero-Downtime Deploy V.IMP

pm2 reload myshop-api    # rolling restart — koi downtime nahi
sudo nginx -t && sudo nginx -s reload   # graceful config reload
Gotchasystemctl restart nginx connections turant kaat deta hai — -s reload use karo, purane workers ko current requests complete karne deta hai.

Production Config — sab kuch ek jagah V.IMP

server {
  listen 443 ssl;
  server_name myshop.com;
  ssl_certificate     /etc/letsencrypt/live/myshop.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/myshop.com/privkey.pem;
  root /var/www/myshop/dist;
  index index.html;
  client_max_body_size 20M;
  gzip on;
  location / { try_files $uri $uri/ /index.html; }
  location /api/ {
    proxy_pass http://backend_servers/;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 10s;
  }
}

Interview mein aksar poocha jaata hai: "production config likho" — isi tarah SSL + static/SPA + body-size/gzip + proxy headers/timeout combine karke dikhao.

Poora syllabus ek line mein: Nginx = reverse proxy + LB + SSL termination → Master/Worker se high concurrency → config events→http→server→location, priority location>server>http → proxy_pass/proxy_set_header se backend ko forward + real client info do → Certbot se free auto-renewing HTTPS → upstream + round-robin/weight/least_conn/ip_hash se load balance → static root/alias/try_files + SPA fallback + cache-busting hash → gzip/keepalive/proxy_cache/timeouts se performance → rate-limit/headers/CORS/SSL-hardening se security → access/error log + status codes se debug → PM2 + graceful reload se zero-downtime production.
⚡

Rapid-fire Interview Q&A

Bolo aur khud test karo — answer chhupa hai (hover/select nahi, bas yaad karo)

  1. Nginx 3 kaam? Web server, reverse proxy, load balancer (+ SSL/cache).
  2. Master vs Worker? Master manage karta hai, Worker requests handle karta hai (event-driven).
  3. Nginx event-driven kyun fast? Single-threaded per worker but non-blocking, epoll/kqueue se 1000s conn.
  4. proxy_pass trailing slash effect? Prefix strip hota hai ya nahi — 404 ka common cause.
  5. X-Real-IP kyun chahiye? Warna backend ko sab requests 127.0.0.1 se aati dikhti hain.
  6. 502 vs 504? 502 = backend down/crashed; 504 = backend slow, timeout cross.
  7. Round Robin vs least_conn? RR turn-wise; least_conn = jisme abhi kam connections.
  8. ip_hash kab use? Session server memory mein ho, sticky session chahiye.
  9. root vs alias? root path append karta hai, alias replace.
  10. SPA 404 on refresh — fix? try_files $uri $uri/ /index.html;
  11. client_max_body_size default? 1MB — file upload ke liye badhana padta hai.
  12. nginx -s reload vs systemctl restart? reload graceful (no downtime); restart connections cut karta hai.
  13. Certbot kya automate karta hai? Cert issue + Nginx config + HTTP→HTTPS redirect + auto-renewal.
  14. Let's Encrypt cert validity? 90 din, auto-renew cron/systemd timer se.
  15. Config change ke baad pehla command? nginx -t — syntax check, phir reload.
  16. gzip kyun on karte hain? Response size chhota (200KB→~50KB), fast load.
  17. proxy_cache ka fayda? Repeated requests DB tak nahi jaati — DB load kam.
  18. Rate limiting kis attack se bachata hai? Brute-force / login abuse — 429 error deta hai limit ke baad.
  19. HSTS header kya karta hai? Browser ko force karta hai hamesha HTTPS use kare.
  20. Site down — troubleshoot order? nginx -t → error.log → systemctl status → curl backend → reload.
