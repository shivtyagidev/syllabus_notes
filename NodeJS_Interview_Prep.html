⚡ Priority 1: Event Loop, Libuv & Concurrency Internals

Node.js ka #1 interview filter. Yahan interviewer check karta hai ki aap sirf syntax jante hain ya core internals bhi.

🧠 Ek Line Mein Yaad Rakhne Ki Trick:

  1. Event Loop 6 Phases: "Timers → Pending → Idle → Poll (I/O) → Check (setImmediate) → Close". Short trick: "The Pilot Is Pretty Cool Captain".
  2. Microtasks Priority: process.nextTick > Promise.then / queueMicrotask > Macrotasks (Timers / I/O / setImmediate).
  3. Golden Rule: "JavaScript single-threaded hai, lekin Node.js multi-threaded hai via Libuv Thread Pool (default 4 threads)."
# Scenario Question Main Cause Fix / Approach Easy Explain (yaad trick) Quick Interview Answer
🔄 Event Loop & Queues
1 Node.js single-threaded hai to 10,000 concurrent requests kaise handle karta hai? Non-blocking I/O + OS Kernel multiplexing (epoll/kqueue) + Libuv thread pool I/O operations OS kernel ko delegate hoti hain. JS thread wait nahi karta, request aate hi agle kaam par lag jaata hai. Restaurant Waiter Trick: Ek hi waiter (single thread) order lekar kitchen ko deta hai aur doosre table par chala jata hai. Har table ke liye naya waiter nahi khada hota. "Node.js uses non-blocking I/O with an event-driven architecture via Libuv. I/O tasks are delegated to the OS kernel or thread pool, freeing the main thread to serve subsequent requests immediately."
2 process.nextTick() aur setImmediate() mein kya difference hai? Kaun pehle chalega? nextTick Event Loop phase ka part nahi hai; yeh current phase ke turant baad run hota hai. setImmediate Check phase mein chalta hai. process.nextTick always runs BEFORE setImmediate and even before Promise microtasks in the current tick. Name Paradox Trick: Dono ke naam ultay hain! nextTick abhi (immediately) chalta hai, aur setImmediate agle tick ke Check phase mein chalta hai. "process.nextTick executes immediately after the current operation before the event loop continues, having higher priority than microtasks. setImmediate executes in the Check phase of the event loop."
3 Heavy CPU calculation (jaise 50MB JSON stringify ya crypto) se server hang ho gaya. Kyun aur kaise fix karoge? Main thread block ho gaya, jisse Event Loop ruk gaya aur baaki users ki requests queue mein stuck ho gayi. 1) worker_threads use karo CPU tasks ke liye.
2) Heavy loop ko setImmediate() se chunk karo.
3) Separate microservice banao.		 Counter Jam Trick: Ek customer counter par 1 ghante tak calculation karega to peeche sab ruk jayenge. Calculation ko doosre room (Worker Thread) mein bhej do! "CPU-bound tasks block the V8 event loop. I offload CPU-intensive operations to Worker Threads or break long iterations using setImmediate() so the event loop keeps processing I/O."
4 Libuv Thread Pool mein kaun kaun se operations jaate hain? Kya saare I/O thread pool mein jaate hain? Interview trap: Saare I/O nahi jaate! Network I/O (HTTP, TCP, UDP) OS epoll/kqueue par chalta hai, thread pool par nahi! Thread pool sirf 4 cheezon ke liye use hota hai: 1) File system (fs), 2) DNS lookup (dns.lookup), 3) Crypto (crypto.pbkdf2), 4) Zlib compression. F-D-C-Z Formula: File, Dns, Crypto, Zlib. Network requests OS sambhalta hai, Libuv threads nahi. Default threads = 4 (UV_THREADPOOL_SIZE). "Only File I/O, DNS lookup, Crypto, and Zlib use the Libuv thread pool. Network I/O is handled directly by non-blocking OS system calls like epoll/kqueue without thread pool overhead."
5 Worker Threads vs Child Process vs Cluster Module: Kab kaun sa use karoge? Resource sharing vs process isolation ke alag requirements 1) Cluster: Multiple CPU cores utilize karke HTTP throughput badhane ke liye.
2) Worker Threads: Same memory share karke heavy computation (image processing/encryption) ke liye.
3) Child Process: External shell commands ya Python script run karne ke liye.		 Cluster = 4 Branches (har core par independent app).
Worker = 1 Room mein 4 Helpers (shared memory).
Child = Bahar ke contractor ko bulana (separate OS process).		 "I use Cluster/PM2 to scale web traffic across multiple CPU cores. I use Worker Threads for CPU-heavy tasks requiring shared memory. I use Child Process to execute external CLI commands or scripts."

🧠 Priority 2: Memory Leaks, V8 Heap & Garbage Collection

Production mein Node.js app crash hone ka sabse bada reason: FATAL ERROR: Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory.

🧠 Memory Leaks Ki 4 Common Bimariyan:

  1. Global Variables / In-Memory Objects: Bina eviction ke cache[userId] = data store karna.
  2. Forgotten Timers: setInterval chalte rehna jisme closure data pakad kar rakhta hai.
  3. EventEmitter Listener Leak: eventEmitter.on() loop mein call hona bina removeListener() ke.
  4. Closures: Outer function ke bade buffers ya objects ko reference karke unkillable bana dena.

💾 Memory & Garbage Collection
6 Node.js server 2 din chalne ke baad `heap out of memory` dekar crash ho jaata hai. Root cause kaise dhundoge? Memory leak (objects heap se GC nahi ho rahe hain) 1) node --inspect flag se Chrome DevTools connect karo.
2) 2 Heap Snapshots lo (ek load se pehle, ek load ke baad).
3) "Comparison" view mein dekho kaun se objects # Alloc mein grow ho rahe hain.		 Weight Scale Trick: Pehle weight lo, 1 ghanta chalao, fir weight lo. Jo cheez lagatar badh rahi hai aur kabhi ghati nahi, wahi leak hai. "I inspect heap snapshots using Chrome DevTools or Clinic.js Heap Profiler under simulated traffic, compare snapshot deltas, and locate retained objects that aren't being garbage collected."
7 Terminal mein warning aati hai: MaxListenersExceededWarning: Possible EventEmitter memory leak detected. Iska kya matlab hai? Ek hi event par 10 se zyada listeners attach ho gaye (Node default limit 10 hoti hai). Often happens jab request handler ke andar stream.on('data') baar baar register hota hai. 1) .once() use karo agar ek baar chalana hai.
2) Ya stream.removeListener() / cleanup function call karo request complete hone par.
3) emitter.setMaxListeners() tabhi badhao jab valid reason ho.		 Meeting Invitation Trick: Har nayi request par purana listener hataye bina naya listener jodte jaoge to crowd badhta jayega aur memory bhar jayegi. "This warning fires when more than 10 listeners are attached to an EventEmitter, usually caused by adding event handlers inside request loops without removing them on completion."
8 V8 Garbage Collector kaise kaam karta hai? Scavenge aur Mark-Sweep mein kya antar hai? Generational Hypothesis: "Most objects die young." V8 memory ko do parts mein baant-ta hai:
1) Young Generation (New Space): Chote objects ke liye fast Scavenge algorithm (Semi-space copy).
2) Old Generation: Jo objects bach jaate hain wo Old space mein promote hote hain, jahan Mark-Sweep-Compact chalta hai.		 College Hostel Trick: Freshers room (New Space) mein fast clean up hota hai. Jo survive kar jate hain wo Senior room (Old Space) mein jate hain jahan deep cleaning (Mark-Sweep) hoti hai. "V8 uses generational garbage collection. New short-lived objects are rapidly collected in Young Space via Cheney's scavenge algorithm. Surviving objects migrate to Old Space, managed by Mark-Sweep-Compact."

🌊 Priority 3: Streams, Buffers & Backpressure

Badi files aur streaming data pipelines ka interview question. Agar stream ka concept clear hai to interviewer impress ho jaata hai.

# Scenario Question Main Cause Fix / Approach Easy Explain (yaad trick) Quick Interview Answer
📦 Data Pipelines
9 1GB file user ko download karwani hai. fs.readFile() crash ho gaya, sahi solution kya hai? fs.readFile() poori file ek sath RAM buffer mein load karta hai. Agar server par 500MB free RAM hai to 1GB padhte hi process crash ho jayega. fs.createReadStream() + pipeline() use karo. Yeh data ko chote chunks (default 64KB) mein read karke stream karega. Gulping vs Sipping: Puri balti ek sath peene ki koshish karoge to dum ghutega (RAM crash). Straw se sip-sip karke peeyo (Streams, only 64KB at a time). "fs.readFile buffers the entire file into memory causing memory exhaustion. I use fs.createReadStream piped to the HTTP response using stream.pipeline, keeping memory consumption minimal (around 64KB)."
10 Stream mein Backpressure kya hota hai? Agar handle na karein to kya hoga? Fast Producer (Read stream) aur Slow Consumer (Slow network socket/write stream) ka speed mismatch. Data RAM buffer mein accumulate hone lagta hai. Jab write stream ka internal buffer bhar jata hai to write() return false karta hai. Producer ko readStream.pause() karna hota hai aur drain event aane par readStream.resume() karna hota hai. Or simply use pipeline(). Funnel Overflow Trick: Pipe mein upar se motor se paani daal rahe ho aur niche se chota sa ched hai. Paani bahar girne lagega. Paani roko jab tak funnel khali na ho (drain)! "Backpressure occurs when data is read faster than the consumer can write, filling up the internal buffer. Node automatically handles this via stream.pipeline by pausing the reader until the writer emits the 'drain' event."
11 pipe() ke bajaye stream.pipeline() use karna kyun recommended hai? .pipe() stream error hone par dest streams ko properly destroy nahi karta, jisse file descriptor aur memory leak ho jaati hai. stream.pipeline(readStream, transformStream, writeStream, (err) => {}) sabhi streams ko automatically destroy aur clean up karta hai agar koi bhi error aaye. Automatic Switch Off: Purani pipe toot-ti thi to paani behta rehta tha. pipeline() pipeline toot-te hi main supply band kar deta hai. "stream.pipeline automatically closes and destroys all streams in the chain if any stream fails or errors out, preventing file descriptor leaks that occur with standard .pipe()."

🛡 Priority 4: Express.js Architecture & Production Reliability

Middleware mechanics, Error handling, aur Graceful shutdown: Real-world production code standard.

# Scenario Question Main Cause Fix / Approach Easy Explain (yaad trick) Quick Interview Answer
⚙ Production Best Practices
12 Global Error Handling Middleware mein 4 arguments (err, req, res, next) hona zaroori kyun hai? Agar 3 args likhe to kya hoga? Express.js internal routing middleware function ke fn.length (parameters count) se pehchanta hai ki yeh standard middleware hai ya error handler. Agar aap 3 arguments likhenge (err, req, res) to Express use standard middleware maan lega aur next(err) aane par use skip kar dega! Isliye 4 arguments mandatory hain. Uniform Rule: Security guard 4 star badge dekh kar hi alert room mein enter karne deta hai. 3 star hue to standard employee manega. "Express inspects the function's arity (fn.length). Exactly 4 arguments (err, req, res, next) signify an error handler; otherwise Express treats it as a standard request middleware."
13 Production server par Graceful Shutdown kaise implement karte ho? Naya deployment ya container restart hote hi chal rahi active requests beech mein terminate ho jati hain aur database connections abruptly cut jate hain. 1) process.on('SIGTERM') aur SIGINT listen karo.
2) server.close() call karo (taaki nayi requests aana band ho aur active requests complete ho sakein).
3) DB connection pool close karo.
4) Timeout fail-safe (10s) lagao, phir process.exit(0).		 Restaurant Closing Trick: Dukan badhte waqt naye customers ko mana karte hain, jo log kha rahe hain unhe khila kar bill lekar hi shutter girate hain. "I listen for SIGTERM/SIGINT, call server.close() to finish ongoing requests while rejecting new ones, drain DB pools, and enforce a 10s fallback timeout before process.exit(0)."
14 uncaughtException aur unhandledRejection aane par process ko restart karna zaroori kyun hai? Kya sirf log karke continue kar sakte hain? Ek unhandled exception ke baad Node process unpredictable corrupt state mein chala jaata hai (leaked sockets, inconsistent memory). Error log karo, monitoring alert bhejo, aur process ko process.exit(1) karke PM2/Kubernetes ko clean restart karne do. Never keep running after uncaughtException! Airplane Engine Failure Trick: Engine mein aag lage to bas logbook mein likh kar udte nahi reh sakte, land karke naya engine start karna hi padega. "An uncaughtException leaves application state corrupted and unpredictable. Best practice is to log the stack trace, initiate graceful cleanup, exit with code 1, and let PM2 or Kubernetes restart a clean instance."

🌐 Priority 5: REST APIs, PUT vs PATCH & Status Codes

Slide 100 aur interviewer ka favourite topic: Idempotency, HTTP Methods aur Status code standard design.

# Scenario Question Main Cause Fix / Approach Easy Explain (yaad trick) Quick Interview Answer
📡 HTTP & REST Design
15 PUT vs PATCH mein kya core difference hai? Dono mein Idempotency ka kya role hai? Full Replacement (PUT) vs Partial Modification (PATCH) PUT: Pure resource ko new payload se replace karta hai (jo field nahi bhejenge wo null/delete ho jayegi). Idempotent hai.
PATCH: Sirf diye gaye fields ko update karta hai. Technically Non-idempotent ho sakta hai (e.g. { $inc: { age: 1 } }).		 Form Trick: PUT = Pura naya form submit karna.
PATCH = Form ke sirf mobile number par whitener laga kar naya number likhna.		 "PUT replaces the entire entity with the provided payload and is idempotent. PATCH applies partial modifications to specific fields and is not inherently guaranteed to be idempotent."
16 HTTP Status Code 401 Unauthorized vs 403 Forbidden mein kya antar hai? Authentication (Pehchan) vs Authorization (Haqq/Permissions) 401 Unauthorized: User logged in nahi hai ya token missing/invalid hai ("Tum kaun ho?").
403 Forbidden: User pehchaana gaya hai, lekin uske paas is route ka permission nahi hai ("Tumhe andar aane ki ijazat nahi hai").		 Entry Gate Trick: ID card nahi hai = 401.
Student ID card hai par Principal room mein ghusna chahta hai = 403.		 "401 means unauthenticated (missing or invalid credentials), prompting for login. 403 means authenticated but unauthorized (user lacks necessary roles/permissions to access the resource)."
17 204 No Content kab use karte hain? Kya 204 mein response body bhej sakte hain? HTTP Spec rule: 204 response must not have a message body. DELETE request successful hone par ya PATCH update ke baad jab client ko naya data return karne ki zaroorat na ho. Browser 204 aane par UI view change nahi karta. Thumbs Up Trick: "Kaam ho gaya, kehne ko kuch nahi hai" 👍. Body empty honi chahiye. "204 No Content indicates successful execution where no response body needs to be returned, commonly used for DELETE or update operations."

🔑 Security & Auth Architecture
18 User ne "Logout" click kiya. JWT to stateless hai, client ne token save kar rakha ho to use kaise invalidate karoge? JWT self-contained cryptographically signed string hoti hai, server par iska state nahi hota. Expiry se pehle wo valid rehti hai. 1) Redis Blacklist: Logout par token ki remaining validity ke TTL ke sath token hash Redis mein save karo. Middleware mein Redis check karo.
2) Token Version / Refresh Token Rotation: User document mein tokenVersion maintain karo.		 Security Bouncer Blacklist: VIP pass par time likha hai, par chor ne chura liya to gatekeeper ki diary (Redis) mein likh do "Pass #123 reject karo". "Since JWT is stateless, I invalidate it on logout by adding its JTI (unique ID) to a Redis blacklist with a TTL equal to the token's remaining lifespan, or by incrementing a user tokenVersion in the database."
19 Access Token + Refresh Token flow kyun zaroori hai? Dono ko kahan store karna chahiye? Security vs User experience tradeoff. Agar Access token 30 din ka hoga to chori hone par 30 din tak hacker use kar sakta hai. 1) Access Token: Short-lived (10–15 mins), memory ya secure state mein.
2) Refresh Token: Long-lived (7 days), strictly in HttpOnly, Secure, SameSite Cookie (XSS immune) + DB/Redis rotation.		 Cash vs ATM Card: Jeb mein 500 rupaye (Access Token - chori ho to chota nuksan). ATM card (Refresh Token) safe locker mein pin ke sath. "Access tokens are short-lived (15m) to limit vulnerability windows. Refresh tokens are long-lived and stored in HttpOnly, Secure, SameSite cookies to mitigate XSS attacks while maintaining seamless re-authentication."

2) IN (...) query use karo (WHERE userId IN (1,2,3...50)).
3) GraphQL mein DataLoader use karo jo automatic batching & caching karta hai.		 Grocery Store Trip Trick: 50 items lene ke liye 50 baar dukaan jaana vs ek hi list banakar ek hi trip mein saara samaan lana. "The N+1 problem occurs when fetching children inside a loop of N parents. I resolve it using SQL JOINs, batch queries with IN clauses, or DataLoader for automated request batching and caching."

🛡 1. Production Graceful Shutdown

Zero downtime deployments aur clean cleanup (HTTP server + DB connection pool).

const server = app.listen(PORT, () => console.log(`Server on ${PORT}`));

function shutdown(signal) {
  console.log(`Received ${signal}. Shutting down gracefully...`);
  
  // 1. Stop taking new requests
  server.close(async () => {
    console.log('HTTP server closed.');
    try {
      // 2. Close database pools
      await dbPool.end();
      console.log('Database pool drained.');
      process.exit(0);
    } catch (err) {
      console.error('Error during shutdown:', err);
      process.exit(1);
    }
  });

  // 3. Force exit after 10s if stuck
  setTimeout(() => {
    console.error('Forced shutdown due to timeout.');
    process.exit(1);
  }, 10000).unref();
}

process.on('SIGTERM', () => shutdown('SIGTERM'));
process.on('SIGINT', () => shutdown('SIGINT'));

🌊 2. Safe Stream Pipeline with Backpressure

Memory leak free file streaming with stream.pipeline.

const fs = require('fs');
const { pipeline } = require('stream');
const zlib = require('zlib');

app.get('/download-log', (req, res) => {
  const readStream = fs.createReadStream('/var/log/large.log');
  const gzipStream = zlib.createGzip();

  res.setHeader('Content-Encoding', 'gzip');
  res.setHeader('Content-Type', 'text/plain');

  // Automatically manages backpressure & destroys streams on error
  pipeline(readStream, gzipStream, res, (err) => {
    if (err) {
      console.error('Pipeline failed:', err);
      if (!res.headersSent) res.status(500).send('Streaming error');
    } else {
      console.log('Stream completed successfully!');
    }
  });
});

⚡ 3. Redis Cache-Aside Pattern with Jitter

Thundering herd prevent karne ke liye randomized TTL caching.

async function getProductById(productId) {
  const cacheKey = `product:${productId}`;

  // 1. Try cache first
  const cached = await redis.get(cacheKey);
  if (cached) return JSON.parse(cached);

  // 2. Cache miss -> Query DB
  const product = await db.query('SELECT * FROM products WHERE id = $1', [productId]);
  if (!product) return null;

  // 3. Add Jitter: 300s + (0 to 30s) to prevent simultaneous stampede
  const jitterSeconds = Math.floor(Math.random() * 30);
  const ttl = 300 + jitterSeconds;

  await redis.set(cacheKey, JSON.stringify(product), 'EX', ttl);
  return product;
}

🔑 4. JWT Middleware with Token Blacklisting

Immediate logout revocation via Redis check.

async function authenticateToken(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];

  if (!token) return res.status(401).json({ message: 'Token missing' });

  // 1. Check if token is in Redis blacklist (logged out)
  const isBlacklisted = await redis.get(`bl_${token}`);
  if (isBlacklisted) {
    return res.status(401).json({ message: 'Token has been revoked. Please log in again.' });
  }

  // 2. Verify JWT signature & expiration
  jwt.verify(token, process.env.ACCESS_TOKEN_SECRET, (err, user) => {
    if (err) return res.status(403).json({ message: 'Token invalid or expired' });
    req.user = user;
    next();
  });
}
