Angular Core

Angular Architecture V.IMP

Angular = component-based framework. Building blocks: Modules (NgModule — code organize), Components (UI+logic), Templates (HTML+Angular syntax), Services (shared logic/data via DI), Directives (DOM behavior), Pipes (display transform), Router (navigation).

Flowmain.ts root component bootstrap karta hai → component tree render → template ↔ class sync change detection se → services DI se shared data/logic provide karte hain.
Interview gotchaAngular 14+ mein standalone components aaye — NgModule optional ho gaya (component khud imports: [] define karta hai). Detail Phase 2 mein.

Component Anatomy V.IMP

@Component({
  selector: 'app-user-card',
  templateUrl: './user-card.component.html',
  styleUrls: ['./user-card.component.css']
})
export class UserCardComponent {
  @Input() user!: User;
}
  • selector — custom HTML tag jisse component use hota hai.
  • template/templateUrl — inline ya external HTML.
  • styleUrls — component-scoped CSS.
Interview gotchaComponent styles default encapsulated hote hain (attribute-based, shadow-DOM jaisa) — global CSS leak nahi karti, jab tak ViewEncapsulation.None na ho.

Templates & Syntax

Template = HTML + Angular-specific syntax jo component class se connect hota hai.

  • {{ expression }} — interpolation (text content).
  • #ref — template reference variable (DOM element/component instance ka local handle).
  • ?. — safe navigation, null/undefined pe crash nahi hota.
GotchaTemplate expressions mein assignment (=), new, ++ allowed nahi — sirf simple read expressions, side-effects component class mein hi rakho.

Data Binding — 4 Types V.IMP

TypeSyntaxDirectionExample
Interpolation{{ expr }}Component → View{{ user.name }}
Property binding[prop]="expr"Component → View[disabled]="isLoading"
Event binding(event)="handler($event)"View → Component(click)="save()"
Two-way binding[(ngModel)]="prop"Both[(ngModel)]="username"
Banana in a box[(ngModel)] = [ngModel] (property bind) + (ngModelChange) (event bind) ka shorthand — isi shape se "banana in a box" naam pada.
Interview gotchaTwo-way binding ke liye FormsModule import chahiye (template-driven). Reactive forms mein [formControl] use hota hai, ngModel nahi.

Directives — Structural vs Attribute V.IMP

TypeExamplesKya karte hain
Structural*ngIf, *ngFor, *ngSwitchDOM add/remove — * prefix = <ng-template> sugar
AttributengClass, ngStyleAppearance/behavior change, DOM structure same rehta hai
GotchaEk element pe do structural directives ek saath nahi laga sakte (e.g. *ngIf + *ngFor same tag) — wrapper <ng-container> use karo.

Custom Directive V.IMP

@Directive({ selector: '[appHighlight]' })
export class HighlightDirective {
  @Input() appHighlight = 'yellow';
  constructor(private el: ElementRef, private renderer: Renderer2) {}

  @HostListener('mouseenter') onEnter() {
    this.renderer.setStyle(this.el.nativeElement, 'background', this.appHighlight);
  }
  @HostListener('mouseleave') onLeave() {
    this.renderer.removeStyle(this.el.nativeElement, 'background');
  }
}
Real useReusable hover-highlight, role-based show/hide, auto-focus directive.
Interview gotchaDOM manipulation seedha ElementRef.nativeElement se mat karo — Renderer2 use karo (SSR-safe, XSS-safer, platform-agnostic).

Pipes — Built-in, Custom, Pure vs Impure V.IMP

Pipe = display-time data transform, template mein | se use hota hai, chain bhi kar sakte ho.

Built-indate, currency, uppercase/lowercase, decimal, percent, json, slice, keyvalue, async.
{{ price | currency:'INR':'symbol':'1.2-2' }}
{{ user$ | async }}
@Pipe({ name: 'truncate' })
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit = 20): string {
    return value.length > limit ? value.slice(0, limit) + '…' : value;
  }
}
Interview gotcha — Pure vs ImpurePure (default): sirf input reference change hone par re-run. Impure (pure: false): har change detection cycle mein re-run. Array/object filter pipe pure hai toh mutate karne se UI update nahi hogi — naya reference do; impure banana perf hit deta hai.

Component Lifecycle Hooks — Execution Order V.IMP

#HookKab chalta hai
1constructorDI resolve hoti hai — @Input abhi undefined
2ngOnChanges@Input bound property change hote hi (pehli baar bhi), reference-change based
3ngOnInitPehle ngOnChanges ke baad, ek hi baar — data fetch/init logic yahan
4ngDoCheckHar change detection cycle mein — custom change detection
5ngAfterContentInitng-content se projected content init hone ke baad, ek baar
6ngAfterContentCheckedHar CD cycle, projected content check hone ke baad
7ngAfterViewInitComponent + child views fully init, ek baar — yahi se ViewChild available
8ngAfterViewCheckedHar CD cycle, view check hone ke baad
9ngOnDestroyComponent destroy hone se pehle — cleanup: unsubscribe, clearInterval
Interview gotchangOnChanges sirf @Input-bound properties ke liye fire hota hai, aur sirf jab reference change ho (array.push() se nahi chalega, naya array assign karna padega).
Real scenario"Component destroy hone ke baad API/subscription chal rahi hai" — fix: ngOnDestroy mein takeUntil ya Subscription.unsubscribe(), warna memory leak.

Parent → Child / Child → Parent V.IMP

// child
@Input() product!: Product;
@Output() addToCart = new EventEmitter<Product>();
onClick() { this.addToCart.emit(this.product); }
<app-product [product]="item"
  (addToCart)="handleAdd($event)">
</app-product>
Gotcha@Input() setter use karke bhi change pe react kar sakte ho — ngOnChanges ka alternative, especially jab sirf ek property track karni ho.

ViewChild / ViewChildren V.IMP

@ViewChild('nameInput')
nameInput!: ElementRef<HTMLInputElement>;

@ViewChild(ChildComponent) child!: ChildComponent;
@ViewChildren(ItemComponent) items!: QueryList<ItemComponent>;

ngAfterViewInit() {
  this.nameInput.nativeElement.focus();
}
Interview gotchaReference ngOnInit mein undefined hota hai — sirf ngAfterViewInit ke baad available. static: true chahiye agar element *ngIf ke andar nahi hai aur usse pehle access karna ho.

Content Projection — ng-content

<!-- card.component.html -->
<div class="card">
  <ng-content select="[card-header]"></ng-content>

</div>

<!-- usage -->

Phase 1 ek line mein: Angular = modules + components (template ↔ class) + services(DI) architecture → 4-type data binding (interpolation/property/event/two-way) → structural vs attribute directives + custom directive (Renderer2) → pure/impure pipes → 9-step lifecycle (constructor→OnChanges→OnInit→DoCheck→AfterContent*→AfterView*→OnDestroy) → @Input/@Output se parent-child communication → ViewChild sirf AfterViewInit ke baad → ng-content se reusable wrapper components.

Phase 1 Rapid-fire Q&A

Bolo aur khud test karo — answer chhupa hai (hover/select nahi, bas yaad karo)

  1. Component vs Directive? Component = template wala directive; plain directive ka apna template nahi hota.
  2. Interpolation vs property binding kab use karo? Text content ke liye interpolation, non-string/attribute (disabled, src) ke liye property binding.
  3. *ngIf ka desugared form? <ng-template [ngIf]="cond">.
  4. Pure pipe kab re-run hota hai? Sirf jab input ka reference change ho.
  5. ngOnChanges kab nahi chalega? Jab @Input object/array mutate ho (reference same rahe) ya property @Input na ho.
  6. Lifecycle mein ViewChild kab available hota hai? ngAfterViewInit ke baad, ngOnInit mein undefined.
  7. ngOnDestroy mein kya karna chahiye? Subscriptions unsubscribe, timers clear — memory leak se bachne ke liye.
  8. Banana in a box kya hai? [(ngModel)] — property + event binding ka combo shorthand.
  9. Two structural directives ek element pe kyun nahi? Angular allow nahi karta — <ng-container> se wrap karo.
  10. Renderer2 kyun use karte ho, nativeElement seedha kyun nahi? SSR-safe, platform-agnostic, XSS-safer.
  11. ng-content ka select attribute kya karta hai? Multi-slot projection — specific matching elements ko specific slot mein bhejta hai.
  12. @Input setter ka use kab karo? Jab ek specific property ke change pe hi react karna ho, poore ngOnChanges object se avoid karne ke liye.
