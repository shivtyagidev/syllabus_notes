1. JavaScript Introduction & How It Works Basic

What is JavaScript?

JavaScript is a lightweight, interpreted, single-threaded, dynamic, weakly-typed programming language. It runs in browsers (client-side) and on servers (Node.js - server-side).

Key Facts for Interview:
• JS is single-threaded — one call stack, one thing at a time
• JS is dynamically typed — variable types determined at runtime
• JS uses prototype-based inheritance, not class-based (classes are syntactic sugar)
• JS is interpreted by the JS Engine (V8 in Chrome/Node, SpiderMonkey in Firefox)

How JavaScript Engine Works

When JS code runs, the engine does:

  1. Parsing — Converts code to AST (Abstract Syntax Tree)
  2. Compilation — JIT (Just-In-Time) compiles AST to bytecode
  3. Execution — Executes bytecode

Execution Context

Every time JS runs code, it creates an Execution Context. Two types:

  • Global Execution Context (GEC) — Created when script first runs
  • Function Execution Context (FEC) — Created when a function is called

Each Execution Context has two phases:

// Phase 1: CREATION PHASE (Memory Allocation)
// - var variables stored as undefined
// - function declarations stored completely
// - 'this' is set

// Phase 2: EXECUTION PHASE
// - Code runs line by line
// - Variables get their actual values

function greet() {
  console.log(message);  // undefined (hoisted, not yet assigned)
  var message = "Hello";
  console.log(message);  // "Hello"
}
greet();

Call Stack

function first() {
  second();
  console.log("first");
}
function second() {
  third();
  console.log("second");
}
function third() {
  console.log("third");
}
first();

// Call Stack (LIFO):
// 1. main() pushed
// 2. first() pushed
// 3. second() pushed
// 4. third() pushed → executes → popped
// 5. second() continues → popped
// 6. first() continues → popped
// Output: "third", "second", "first"

2. Variables: var, let, const Basic

Variable = data ka container. JavaScript mein 3 tarike hain variables declare karne ke: var, let, const. Inke beech scope, hoisting aur reassignment mein fark hai.

Theory — Key Points:
• var — Function scoped, puri function mein accessible. Hoisting hoti hai (undefined se initialize). Same naam se redeclare ho sakta hai.
• let — Block scoped ({} ke andar). Hoisting hoti hai lekin TDZ mein rehta hai. Redeclare nahi ho sakta.
• const — Block scoped. Declare ke time initialize karna zaroori. Reassign nahi ho sakta. Objects/arrays ke contents change ho sakte hain (reference same rehta hai).
• TDZ (Temporal Dead Zone) — let/const ka wo time jab woh hoist to ho chuke hain but initialize nahi hue — use karo to ReferenceError aayega.
• Scope leaking — var if/for blocks se bahar leak karta hai; let/const nahi karte.
• Best Practice — Hamesha const use karo, sirf jab reassign karni ho tab let. var avoid karo modern JS mein.

var — Function Scoped

function example() {
  if (true) {
    var x = 10;       // function scoped, NOT block scoped
  }
  console.log(x);     // 10 ✅ (accessible outside if block)
}

// var in global scope attaches to window
var name = "Rahul";
console.log(window.name);  // "Rahul" (in browser)

// var can be re-declared
var a = 1;
var a = 2;  // No error
console.log(a);  // 2

let — Block Scoped

function example() {
  if (true) {
    let y = 20;       // block scoped
  }
  console.log(y);     // ❌ ReferenceError: y is not defined
}

// Cannot re-declare
let b = 1;
let b = 2;  // ❌ SyntaxError: Identifier 'b' has already been declared

// Can re-assign
let count = 0;
count = 1;  // ✅

const — Block Scoped, No Re-assignment

const PI = 3.14;
PI = 3;  // ❌ TypeError: Assignment to constant variable

// const with objects — reference is constant, not value!
const person = { name: "Rahul" };
person.name = "Amit";  // ✅ Works! (modifying property, not reference)
person = {};           // ❌ TypeError

// const with arrays
const arr = [1, 2, 3];
arr.push(4);           // ✅ Works!
arr = [5, 6];          // ❌ TypeError

Temporal Dead Zone (TDZ)

// TDZ = time between hoisting and initialization
console.log(a);  // undefined (var is hoisted+initialized)
console.log(b);  // ❌ ReferenceError (let in TDZ)
console.log(c);  // ❌ ReferenceError (const in TDZ)

var a = 1;
let b = 2;
const c = 3;
Interview Tip: Always use const by default. Use let when you need to reassign. Avoid var in modern JS.

3. Data Types Basic

JavaScript mein 8 data types hain — 7 Primitive + 1 Reference (Object). Primitive types Stack mein store hote hain (value ke roop mein). Reference types Heap mein store hote hain (reference ke roop mein).

Theory — Key Points:
• Primitive (7): Number, String, Boolean, null, undefined, Symbol, BigInt — immutable, value copy hoti hai
• Reference (1): Object (Array, Function, Date, RegExp sab objects hain) — reference copy hota hai
• typeof null === "object" — JS ka historic bug, null actually primitive hai
• typeof NaN === "number" — NaN (Not a Number) ka type number hai
• typeof function === "function" — technically object hai lekin typeof "function" return karta hai
• Stack vs Heap — Primitives stack mein hain (fast, fixed size). Objects heap mein (dynamic size). Variable sirf heap ka address store karta hai.
• Copy by value — Primitive copy karo: dono independent. Copy by reference — Object copy karo: dono same object point karte hain.

// PRIMITIVE — copy by value
let a = 10;
let b = a;

console.log(b);  // 20

// REFERENCE — copy by reference

console.log(obj1.x);    // 99 (changed!)

let obj4 = JSON.parse(JSON.stringify(obj1)); // deep copy

5. Operators Basic

Operators kisi value (operand) pe operation perform karte hain. JS mein arithmetic, logical, comparison, assignment, bitwise aur special operators hain.

Theory — Key Points:
• && (AND) — Pehla falsy value return karta hai, ya agar sab truthy to last value
• || (OR) — Pehla truthy value return karta hai, ya agar sab falsy to last value
• ?? (Nullish Coalescing) — Sirf null/undefined pe right side return karta hai (0, "" ko falsy nahi maanta)
• ?. (Optional Chaining) — null/undefined pe expression rok deta hai — TypeError se bachata hai
• === vs == — Strict (===) type + value check karta hai. Loose (==) type coercion karta hai. Hamesha === use karo.
• a++ vs ++a — Post-increment (a++) pehle return karta hai, fir increment. Pre-increment (++a) pehle increment, fir return.
• Short-circuit evaluation — && aur || pure expression evaluate nahi karte agar pehle hi result mil jaye

Arithmetic Operators

let a = 10, b = 3;
a + b   // 13
a - b   // 7
a * b   // 30
a / b   // 3.333...
a % b   // 1 (modulus/remainder)
a ** b  // 1000 (exponentiation, ES2016)
a++     // post-increment (returns 10, then a becomes 11)
++a     // pre-increment (a becomes 11, returns 11)
a--     // post-decrement
--a     // pre-decrement

6. Control Flow Basic

Control flow statements decide karte hain ki code ka kaunsa part kab execute hoga — conditions ke basis pe ya loops ke through.

Theory — Key Points:
• if/else — Complex conditions ke liye, expressions evaluate karta hai (truthy/falsy)
• switch — Ek variable ko multiple values se compare karta hai using strict equality (===). break zaroori warna fallthrough hota hai
• for — Classic loop: init; condition; update. Variable count pata ho tab
• while — Sirf condition check karta hai. Iteration count pata na ho tab
• do...while — Body pehle ek baar zaroor chalti hai, fir condition check
• for...of — Array, String, Map, Set ke VALUES iterate karo
• for...in — Object ke KEYS iterate karo (inherited properties bhi aate hain — hasOwnProperty check karo)
• break — Loop se bahar nikal jao. continue — Current iteration skip karo

if / else if / else

let score = 75;
if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");
} else if (score >= 70) {
  console.log("C");
} else {
  console.log("F");
}
// Output: "C"

switch

const status = "success";

switch (status) {
    case "pending":
        console.log("Order is pending");
        break;

    case "success":
        console.log("Order completed");
        break;

    case "failed":
        console.log("Order failed");
        break;

    default:
        console.log("Unknown status");
}

// switch uses strict equality (===)

Loops

// for loop
for (let i = 0; i < 5; i++) {
  if (i === 3) continue;  // skip 3
  if (i === 4) break;     // stop at 4
  console.log(i);         // 0, 1, 2
}

// while loop
let i = 0;
while (i < 3) {
  console.log(i++);  // 0, 1, 2
}

// do...while — executes at least once
let j = 0;
do {
  console.log(j++);  // 0, 1, 2
} while (j < 3);

// for...of — iterates over values (arrays, strings, sets, maps)
let fruits = ["apple", "banana", "mango"];
for (let fruit of fruits) {
  console.log(fruit);  // apple, banana, mango
}

for (let char of "hello") {
  console.log(char);  // h, e, l, l, o
}

// for...in — iterates over keys/indices (objects, arrays)
let obj = { a: 1, b: 2, c: 3 };
for (let key in obj) {
  console.log(key, obj[key]);  // a 1, b 2, c 3
}
// Note: don't use for...in on arrays (gives string indices + inherited props)

// forEach (array method)
[1, 2, 3].forEach((val, idx) => console.log(idx, val));

7. Functions (All Types) Basic

Functions reusable code blocks hain jo ek specific task perform karte hain. JavaScript mein functions First-Class Citizens (First-Class Objects) hote hain.

🎯 Interview Question: "Why are functions called First-Class Citizens in JS?"
JavaScript mein functions ko First-Class Citizens isliye kehte hain kyunki unhe kisi bhi normal value (number, string) ki tarah treat kiya ja sakta hai:
  1. Variable mein assign ho sakte hain: const fn = function() {};
  2. Doosre functions mein argument (callback) ban kar pass ho sakte hain: arr.map(fn);
  3. Kisi function se return ho sakte hain (Closures & HOFs): return function() {};

Kaunsa Function Kab Use Karein? (Interview Quick Decision Guide)

Function Type Syntax Kab Use Karein? (Use Case) Interview Key Point / Trap
Function Declaration function greet() {} Top-level general utility / helper functions, jise poori file mein upar ya kahin se bhi call karna ho. Fully Hoisted: Definition se pehle bhi call kar sakte ho.
Function Expression const greet = function() {} Conditional function assignment (if/else), objects ya closures ke andar pass/return karne ke liye. Not Hoisted (TDZ): Declare hone se pehle call karoge toh ReferenceError aayega.
Arrow Function (=>) const greet = () => {} Callbacks (map, filter), short 1-liners, aur jahan parent lexical scope ka this retain karna ho. No own this, no arguments, constructor (new) nahi ban sakta. Object methods ke liye mat use karo.
IIFE (function(){})() One-time initialization code, private scope banane ke liye, global scope ko pollute hone se bachane ke liye. Define hote hi turant execute ho jata hai. Variables bahar leak nahi hote.

Pure Function (a, b) => a + b Redux reducers, state management, math/utility calculations jahan 100% predictable output chahiye. Same input → Same output. External state modify nahi karta (Zero side effects).
Callback Function setTimeout(cb, 1000) Asynchronous tasks (APIs, timers) aur event handling (click, submit) handle karne ke liye. Doosre function ko pass hota hai jo task complete hone par ise call back karta hai.
Theory — Key Points:
• Function Declaration — Poori tarah hoist hoti hai. Define karne se pehle bhi call ho sakti hai
• Function Expression — Variable mein store hoti hai. Hoist nahi hoti (var mein undefined, let/const mein TDZ)
• Arrow Function (=>) — Apna this nahi hota (outer this inherit karta hai). arguments object nahi hota. Constructor ke roop mein use nahi ho sakta
• IIFE — Immediately Invoked: define hote hi ek baar execute hoti hai. Private scope banata hai, global pollution se bachata hai
• Higher-Order Function — Function jo doosra function argument mein leta hai ya return karta hai (map, filter, reduce)
• Pure Function — Same input → hamesha same output. Koi side effect nahi. Predictable aur testable
• Callback Function — Woh function jo argument ki tarah doosre function ko dete hain, woh baad mein call karta hai

Higher-Order Functions & Callback Functions

🎯 Kab use karein: Reusable logic abstraction ke liye — jaise custom array transformers, debounce, throttle, currying, ya authorization wrapper functions.

🔑 Ek Line Ka Golden Rule:
• Jo function doosre function ko receive karta hai ya chalata hai — wo Higher-Order Function (HOF) hai.
• Aur jo function argument ban kar andar pass hota hai — wo Callback Function hai.

Real-Life Analogy: Restaurant ka Manager (HOF) order leta hai, aur jo special instruction (Callback) aap dete ho ("Khane mein mirchi kam daalna"), manager cook se wo instruction follow karwata hai.

📖 1. Higher-Order Function (HOF) — Definition

English Definition: A Higher-Order Function is a function that does at least one of the following:

  • Takes one or more functions as arguments (e.g. map(), filter(), setTimeout()).
  • Returns another function as its output/result (e.g. Closures, Currying).

Hinglish Definition: Aisa function jo kisi doosre function ko argument ke roop mein accept kare, YA kisi naye function ko return kare, use Higher-Order Function kehte hain.
Asaan shabdon mein: Jo functions ke saath operate kare (Parent / Controller Function).

📖 2. Callback Function — Definition

English Definition: A Callback Function is a function passed into another function as an argument, which is then invoked (called back) inside that outer function to complete a specific action.

Hinglish Definition: Woh function jo kisi doosre function ko argument ki tarah pass kiya jaata hai, taaki outer function apne execution ke dauran ya baad mein use call kare, use Callback Function kehte hain.
Asaan shabdon mein: Jo function doosre function ke andar chalne ke liye bheja jaata hai (Child / Passed Function).

Interview Point — 2 Types of Callbacks:
• Synchronous Callback: Jo turant execute hota hai bina wait kiye (jaise [1,2,3].map(fn), forEach(fn), filter(fn)).
• Asynchronous Callback: Jo kisi background task ya event ke complete hone ke baad execute hota hai (jaise setTimeout(fn, 1000), fetch().then(fn), button.addEventListener('click', fn)).

1. Simple Custom Example (Dono Ek Saath Kaise Kaam Karte Hain)

// 1. CALLBACK FUNCTION — Yeh function pass hone ke liye bana hai
function makeUppercase(text) {
  return text.toUpperCase();
}

// 2. HIGHER-ORDER FUNCTION — Yeh function ko as argument accept kar raha hai
function processName(name, callback) {
  console.log("Processing name...");
  return callback(name); // Callback ko yahan execute kiya
}

// Call karte waqt:
// processName   → HIGHER-ORDER FUNCTION
// makeUppercase → CALLBACK FUNCTION
const result = processName("rahul", makeUppercase);
console.log(result); // "RAHUL"

2. Daily Built-In JavaScript Examples

// setTimeout → HIGHER-ORDER FUNCTION
// function() { ... } → CALLBACK FUNCTION
setTimeout(function() {
  console.log("2 seconds later!");
}, 2000);

// Example 2: Array.map()
// map → HIGHER-ORDER FUNCTION
// (num) => num * 2 → CALLBACK FUNCTION
const numbers = [1, 2, 3];
const doubled = numbers.map(num => num * 2);
console.log(doubled); // [2, 4, 6]

3. HOF Ka Doosra Roop: Function Return Karna (Closures / Currying)

  return function(number) {
    return number * factor;
  };
}

const triple = multiplier(3);
console.log(double(5)); // 10
console.log(triple(5)); // 15

Interview Key Points & Traps in Functions (Most Asked)

⚠️ Trap 1: Arrow Function inside Object Methods (`this` trap)

The Tricky Question:

const user = {
  name: "Shiv",
  greetRegular: function() { console.log("Hello, " + this.name); },
  greetArrow: () => { console.log("Hello, " + this.name); }
};

user.greetRegular(); // "Hello, Shiv"
user.greetArrow();   // "Hello, undefined"  ← TRAP!

Kyu hua? (Explanation): Arrow functions ka apna this nahi hota. Wo outer lexical scope (window/global/module) se this inherit karte hain jahan name undefined hai.
Rule: Object methods ke liye regular function greet() {} use karo, arrow function nahi!

⚠️ Trap 2: Function Declaration vs Expression Hoisting Trap

The Tricky Question:

foo(); // Output: "I work!" (Fully Hoisted)
bar(); // TypeError: bar is not a function! ← TRAP!
baz(); // ReferenceError: Cannot access 'baz' before initialization! ← TRAP!

function foo() { console.log("I work!"); }
var bar = function() { console.log("I fail!"); };
const baz = function() { console.log("I also fail!"); };

Kyu hua? (Explanation):
• function foo() poori tarah hoist hoti hai (name + body dono memory mein hote hain).
• var bar hoist hokar undefined banta hai, aur undefined() call karne par TypeError aata hai.
• const baz Temporal Dead Zone (TDZ) mein rehta hai, isliye ReferenceError aata hai.

⚠️ Trap 3: Arrow Function Cannot Be Used with `new` (Constructor Trap)

The Tricky Question:

function Person1(name) { this.name = name; }
const p1 = new Person1("Rahul"); // Works! { name: "Rahul" }

const Person2 = (name) => { this.name = name; };
const p2 = new Person2("Rahul"); // TypeError: Person2 is not a constructor! ← TRAP!

Kyu hua? (Explanation): Arrow functions ke paas internal [[Construct]] method aur prototype property nahi hoti, isliye inhe new ke saath constructor function ki tarah use nahi kiya ja sakta.

⚠️ Trap 4: `arguments` Object in Arrow Functions

The Tricky Question:

function normalFn() {
  console.log(arguments); // [Arguments] { '0': 1, '1': 2, '2': 3 }
}
normalFn(1, 2, 3);

const arrowFn = () => {
  console.log(arguments); // ReferenceError: arguments is not defined (browser) ← TRAP!
};
arrowFn(1, 2, 3);

Fix: Arrow functions mein variable arguments ke liye hamesha Rest parameters use karo: const arrowFn = (...args) => console.log(args);.

⚠️ Trap 5: Callback Ke 2 Sabse Bade Disadvantages (Interview Favorite)

Interviewers aksar puchte hain: "Promises kyu aaye? Callbacks mein kya problem thi?"

1. Callback Hell (Pyramid of Doom): Nested async callbacks se code unreadable aur impossible to debug ho jaata hai.
2. Inversion of Control (Trust Issue): Jab hum apna callback kisi 3rd-party ya doosre function ko dete hain, toh control hamare paas nahi rehta. Wo function callback ko 0 baar, multiple baar, ya galat data ke saath call kar sakta hai.
👉 Solution: Promises aur Async/Await ne Inversion of Control aur Callback Hell dono ko solve kiya.

⚠️ Trap 6: Pure Function Mutation Trap (Modifying State)

The Tricky Question:

// IMPURE FUNCTION ❌ (Trap!)
function addItemImpure(arr, item) {
  arr.push(item); // Original array modify ho gaya (Side Effect!)
  return arr;
}

// PURE FUNCTION ✅ (Correct)
function addItemPure(arr, item) {
  return [...arr, item]; // Naya array return kiya, original ko touch nahi kiya!
}

Rule: Pure function external array/object ko push, pop, splice se mutate nahi karta. Hamesha spread operator [...] ya {...} se nayi copy banakar return karta hai (React / Redux principle).

⚠️ Trap 7: `forEach` vs `map` Return Value & Async Trap

• [1,2,3].forEach(x => x * 2) hamesha undefined return karta hai (chaining nahi ho sakti).
• [1,2,3].map(x => x * 2) naya array return karta hai.
• Async Trap: forEach callback ke andar await ka wait nahi karta! Agar sequential async execution chahiye toh for...of loop use karo.

8. Scope & Hoisting Intermediate

Scope decide karta hai ki variable/function kaahan accessible hai. Hoisting JS ka wo behavior hai jisme declarations execution se pehle (creation phase mein) memory mein move ho jaati hain.

Theory — Key Points:
• Global Scope — Har jagah accessible. var global scope mein window object ka property ban jaata hai
• Function Scope — var function ke andar defined hai, bahar accessible nahi
• Block Scope — let/const if/for/while ke {} ke andar bound hote hain
• Lexical Scope — Inner function outer function ke variables access kar sakta hai (basis of closures)
• Scope Chain — Variable dhundhte waqt JS local → outer → global scope mein check karta hai
• Hoisting — var: Declaration top pe aati hai, undefined se initialize hoti hai
• Hoisting — function declaration: Puri function definition top pe aati hai (call karo define se pehle — works!)
• Hoisting — let/const: Declaration hoist hoti hai lekin initialize nahi hoti → Temporal Dead Zone (TDZ)
• TDZ Error: let/const ko declare karne se pehle access karo → ReferenceError

Types of Scope

// 1. Global Scope
var globalVar = "I am global";
let globalLet = "Also global";

// 2. Function Scope

  var localVar = "only inside fn";
  // accessible throughout function
}
// localVar not accessible here

// 3. Block Scope (ES6 with let/const)
{
  let blockVar = "only in block";
  const blockConst = "also only in block";
}
// blockVar not accessible here

// 4. Module Scope (in ES modules, each file has its own scope)

  let middle = "middle";
  function innerFn() {
    let inner = "inner";
    console.log(inner);   // ✅ own scope
    console.log(middle);  // ✅ parent scope
    console.log(outer);   // ✅ grandparent scope

}

9. Closures Advanced

A closure is when a function remembers variables from its outer scope even after that outer function has returned.

// Basic closure
function outer() {
  let count = 0;         // outer variable
  return function() {    // inner function
    count++;
    return count;
  };
}
const increment = outer();  // outer() done, but count lives on
increment();  // 1
increment();  // 2
increment();  // 3

// Each call to outer() creates NEW closure
const c1 = outer();
const c2 = outer();
c1();  // 1
c1();  // 2
c2();  // 1 (independent closure!)

Practical Use Cases

// 1. Data Privacy / Encapsulation
function createBankAccount(initialBalance) {
  let balance = initialBalance;  // private

  return {
    deposit(amount) { balance += amount; },
    withdraw(amount) {
      if (amount > balance) throw new Error("Insufficient funds");
      balance -= amount;
    },
    getBalance() { return balance; }
  };
}
const account = createBankAccount(1000);
account.deposit(500);
account.getBalance();  // 1500
// account.balance   // undefined — truly private!

// 2. Function factories
function makeMultiplier(factor) {
  return (n) => n * factor;
}
const double = makeMultiplier(2);  // factor = 2 remembered
const triple = makeMultiplier(3);
double(5);   // 10
triple(5);   // 15

// 3. Memoization
function memoize(fn) {
  const cache = {};
  return function(...args) {
    const key = JSON.stringify(args);
    if (cache[key]) return cache[key];
    cache[key] = fn(...args);
    return cache[key];
  };
}

// 4. Event handlers
function createButton(label) {
  let clicks = 0;
  return function() {
    clicks++;
    console.log(`${label} clicked ${clicks} times`);
  };
}
const btnHandler = createButton("Submit");

11. call, apply, bind Advanced

These methods allow you to explicitly set this for a function.

function greet(greeting, punctuation) {
  return `${greeting}, ${this.name}${punctuation}`;
}

const person = { name: "Rahul" };

greet.apply(person, ["Hello", "!"]);  // "Hello, Rahul!"

const greetRahul = greet.bind(person);
greetRahul("Hi", ".");                // "Hi, Rahul."

// bind with pre-set args (partial application)
const sayHelloToRahul = greet.bind(person, "Hello");
sayHelloToRahul("!");                 // "Hello, Rahul!"

13. Array Methods Intermediate

Arrays JavaScript ka sabse important data structure hain. Methods do type ke hote hain: mutating (original array change karte hain) aur non-mutating (nayi array return karte hain). Interview mein in dono ka distinction poochha jaata hai.

Theory — Key Points:
• Mutating Methods — push, pop, shift, unshift, splice, sort, reverse, fill → original array change hoti hai
• Non-Mutating Methods — map, filter, reduce, slice, concat, flat, flatMap → nayi array/value return
• map(fn) — har element pe fn apply karo, same size nayi array return karo
• filter(fn) — sirf wahi elements rakho jahan fn → true, chhoti array return
• reduce(fn, init) — array ko single value mein compress karo (sum, object, etc.)
• find vs filter — find pehla matching element deta hai (ya undefined), filter poori array
• some vs every — some: koi ek true ho toh true; every: sab true ho toh true
• flat(depth) — nested arrays ko flatten karta hai; flatMap → map + flat(1) ek step mein
• forEach — koi return value nahi; sirf side effects ke liye; loop break nahi kar sakte
• sort gotcha — default sort strings compare karta hai! Numbers ke liye: arr.sort((a,b) => a-b)

14. Object Methods Intermediate

JavaScript objects ke saath kaam karne ke liye Object.* static methods bahut kaam aate hain. Ye methods mostly non-mutating hain aur objects ko iterate, copy, aur merge karne mein help karte hain.

Theory — Key Points:
• Object.keys(obj) — own enumerable property names ka array (strings)
• Object.values(obj) — own enumerable values ka array
• Object.entries(obj) — [key, value] pairs ka array; Object.fromEntries() → reverse
• Object.assign(target, src) — shallow copy/merge karta hai; target mutate hota hai
• Spread {…obj} — Object.assign se cleaner syntax, bhi shallow copy
• Object.freeze(obj) — object immutable ho jaata hai (add/delete/update block)
• Object.seal(obj) — naye properties add nahi kar sakte, existing update kar sakte hain
• Object.create(proto) — specific prototype chain ke saath object banao
• hasOwnProperty vs 'in' — hasOwnProperty sirf own checks, 'in' prototype chain bhi check karta hai
• Shallow vs Deep Copy — assign/spread sirf top level copy karte hain; nested objects reference share karte hain

• 1. Array Destructuring — Position-based unpacking: const [a, b, c] = numbers;
• 2. Skip Elements — Array elements ko comma chhod kar skip karna: const [x, , z] = numbers;
• 3. Default Value — Agar value missing/undefined ho toh fallback assign karna: const [p, q = 50] = [10];

• 7. Object Default Value — Missing property ke liye default value define karna: const { salary = 50000 } = user;
• 8. Object Rest — Bachi hui properties ko alag object mein collect karna: const { name: n, ...details } = user;
• 9. Nested Object Destructuring — Deeply nested objects ke properties nikalna: const { address: { city: employeeCity, state } } = employee;
• 10. Function Parameter Destructuring — Function argument mein se directly destructure karna: function getUser({ name, age })
• 11. Safe Destructuring — data || {} pattern se null/undefined hone par TypeError (Cannot read properties of null) se bachna

16. Spread & Rest Operators Intermediate

Spread aur Rest dono ek hi syntax (...) use karte hain lekin opposite kaam karte hain. Spread expands karta hai (array/object kholta hai), Rest collects karta hai (baaki values ek jagah laata hai).

Theory — Key Points:
• Spread in Arrays — [...a, ...b] → arrays merge, [...arr] → shallow copy
• Spread in Objects — {...obj1, ...obj2} → merge; duplicate keys mein last value jeetegi
• Spread in Function Call — Math.max(...arr) → array elements ko individual args pass karo
• Rest in Functions — function sum(...nums) → baaki sab arguments ek array mein collect
• Rest in Destructuring — const [first, ...rest] = arr → pehle ke baad sab rest mein
• Spread vs Object.assign — dono shallow copy karte hain; spread cleaner syntax hai
• Shallow Copy Warning — nested objects spread se copy nahi hote, reference copy hota hai
• Rest hamesha last mein — function(a, b, ...rest) ✓ | function(...rest, a) ✗ error!
• arguments vs rest — arguments old way (not in arrow fns), rest modern aur actual array hai

Spread (...) — expand iterables

// Arrays
const a = [1, 2, 3];
const b = [4, 5, 6];

const copy = [...a];                // shallow copy

// Objects
const obj1 = { a: 1, b: 2 };
const obj2 = { b: 3, c: 4 };

function sum(x, y, z) { return x + y + z; }

• Spread: Expands array/object into individual elements (used in function calls, array literals, object literals)
• Rest: Collects multiple elements into an array (used in function params, destructuring)

17. Prototype & Prototype Chain Advanced

Every JS object has an internal [[Prototype]] which is a reference to another object. This forms the prototype chain.

// Every function has a prototype property
function Person(name, age) {
  this.name = name;

}

Person.prototype.species = "Human";

// rahul.greet → not on rahul → check Person.prototype → found!
// rahul.toString → not on rahul → not on Person.prototype → check Object.prototype → found!

Person.prototype.__proto__ === Object.prototype  // true
Object.prototype.__proto__ === null              // true (end of chain)

Object.getPrototypeOf(rahul) === Person.prototype  // true (preferred way)

Prototype Inheritance (before ES6 classes)

function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  return `${this.name} makes a sound`;
};

function Dog(name, breed) {
  Animal.call(this, name);  // call parent constructor
  this.breed = breed;
}
// Set up prototype chain
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;  // fix constructor reference

Dog.prototype.bark = function() {
  return `${this.name} barks!`;
};

const dog = new Dog("Rex", "Labrador");
dog.speak();  // "Rex makes a sound"  (inherited)
dog.bark();   // "Rex barks!"  (own method)
dog instanceof Dog     // true
dog instanceof Animal  // true

What does new do?

// new keyword does 4 things:
// 1. Creates empty object: {}
// 2. Sets __proto__ to Constructor.prototype
// 3. Calls Constructor with this = new object
// 4. Returns the object (unless constructor returns object)

// Manual implementation of new:
function myNew(Constructor, ...args) {
  const obj = Object.create(Constructor.prototype); // steps 1+2
  const result = Constructor.apply(obj, args);       // step 3
  return result instanceof Object ? result : obj;    // step 4
}

18. ES6 Classes & Inheritance Advanced

Classes are syntactic sugar over prototype-based inheritance. Under the hood it's still prototypes.

class Animal {
  // constructor
  constructor(name, sound) {
    this.name = name;
    this.sound = sound;
  }

  // instance method (on prototype)
  speak() {
    return `${this.name} says ${this.sound}`;
  }

  // static method (on class itself, not instances)
  static create(name, sound) {
    return new Animal(name, sound);
  }

  // getter
  get info() {
    return `${this.name} (${this.sound})`;
  }

  // setter
  set info(str) {
    [this.name, this.sound] = str.split(",");
  }
}

const cat = new Animal("Cat", "Meow");
cat.speak();         // "Cat says Meow"
cat.info;            // "Cat (Meow)"
cat.info = "Dog,Woof";
cat.name;            // "Dog"
Animal.create("Bird", "Tweet");  // static call

// Inheritance with extends
class Dog extends Animal {
  constructor(name, breed) {
    super(name, "Woof");  // MUST call super first
    this.breed = breed;
  }

  // override parent method
  speak() {
    return super.speak() + " (loudly)";  // call parent method
  }

  fetch() {
    return `${this.name} fetches the ball!`;
  }
}

const rex = new Dog("Rex", "Labrador");
rex.speak();   // "Rex says Woof (loudly)"
rex.fetch();   // "Rex fetches the ball!"
rex instanceof Dog     // true
rex instanceof Animal  // true

// Private fields (ES2022) — truly private
class BankAccount {
  #balance = 0;  // private field

  deposit(amount) {
    if (amount > 0) this.#balance += amount;
  }
  get balance() { return this.#balance; }
}
const acc = new BankAccount();
acc.deposit(1000);
acc.balance;     // 1000
acc.#balance;    // ❌ SyntaxError (truly private)

• Classes are NOT hoisted (TDZ like let)

• Static methods called on Class, not instances

20. Symbol Advanced

Symbol ES6 ka 7th primitive type hai. Har Symbol unique hota hai, chahe same description ho. Iska main use hai unique property keys banana — jisse name collision avoid ho, especially libraries/frameworks mein.

Theory — Key Points:
• Always Unique — Symbol("x") === Symbol("x") → false! Description sirf debugging ke liye
• Non-enumerable by default — Object.keys() / for...in mein Symbol keys nahi aate
• Object.getOwnPropertySymbols(obj) — Symbol keys dhundhne ka tarika
• Symbol.for(key) — global registry mein Symbol banao/dhundho (same key = same Symbol)
• Well-known Symbols — Symbol.iterator, Symbol.toPrimitive, Symbol.hasInstance → built-in JS behavior customize karo
• Symbol.iterator — apna object iterable banao (for...of use kar sako)
• Use Case — libraries mein private-ish properties, metadata store karna bina collision ke
• Cannot use new — Symbol() ← correct; new Symbol() ← TypeError!

const s1 = Symbol("description");
const s2 = Symbol("description");
s1 === s2  // false! Always unique

class Range {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }
  [Symbol.iterator]() {
    let current = this.start;
    const end = this.end;
    return {
      next() {
        return current <= end
          ? { value: current++, done: false }
          : { value: undefined, done: true };
      }
    };
  }
}

Iterator ek protocol hai — object jiske paas next() method ho jo {value, done} return kare. Generator ek special function hai (function*) jo pause aur resume ho sakta hai, values lazily produce karta hai.

Theory — Key Points:
• Iterator Protocol — next() call karo → {value: ..., done: false/true} milega
• Iterable Protocol — object mein [Symbol.iterator]() ho jo iterator return kare (for...of ke liye zaroori)
• Built-in Iterables — Array, String, Map, Set, arguments sab iterable hain
• Generator function* — yield se pause hota hai; next() call pe resume hota hai
• Lazy Evaluation — Generator values tab compute karta hai jab maango, pehle nahi (memory efficient)
• yield — value bahar bhejta hai aur function pause karta hai; next(val) se value andar bhi bhej sakte ho
• yield* — kisi aur iterable/generator ko delegate karo
• Infinite Sequences — Generator se infinite series bana sakte ho bina memory issue ke
• return() / throw() — generator ko forcefully end karo ya error inject karo

  return result;

22. Proxy & Reflect Advanced

Proxy aapko kisi bhi object ke operations (get, set, delete, etc.) intercept aur customize karne deta hai. Reflect ek built-in object hai jo Proxy traps ke andar default behavior invoke karne ke liye use hota hai.

Theory — Key Points:
• Proxy(target, handler) — target original object, handler mein traps define karo
• get trap — property read intercept karo (validation, logging, default values)
• set trap — property write intercept karo; return true karna zaroori hai (success signal)
• deleteProperty trap — delete operator intercept karo
• has trap — 'in' operator intercept karo
• apply trap — function calls intercept karo (jab target function ho)
• Reflect.get/set/deleteProperty — default behavior invoke karo; Proxy handlers ke andar use karo
• Reflect vs Object methods — Reflect better return values deta hai (boolean success/failure)
• Use Cases — validation, logging, reactive frameworks (Vue 3 ka reactivity Proxy se bana hai!), readonly objects 
// Proxy — intercept and customize object operations
const handler = {
  get(target, prop, receiver) {
    console.log(`Getting ${prop}`);
    return prop in target ? target[prop] : `Property ${prop} not found`;
  },
  set(target, prop, value) {
    if (typeof value !== "number") throw new TypeError("Only numbers!");
    target[prop] = value;
    return true;
  },
  has(target, prop) {
    return prop in target;
  },
  deleteProperty(target, prop) {
    console.log(`Deleting ${prop}`);
    delete target[prop];
    return true;
  }
};

25. Promises Intermediate

A Promise represents the eventual result of an asynchronous operation. It is in one of 3 states: pending, fulfilled, or rejected.

// Creating a Promise
const promise = new Promise((resolve, reject) => {
  // async operation
  const success = true;
  if (success) resolve("Data loaded");
  else reject(new Error("Failed"));
});

// Consuming
promise
  .then(data => console.log(data))       // "Data loaded"
  .catch(err => console.error(err))
  .finally(() => console.log("Done"));

// Chaining (each .then returns a new promise)
fetch("/api/user")
  .then(res => res.json())              // returns promise
  .then(user => fetch(`/api/posts/${user.id}`))
  .then(res => res.json())
  .then(posts => console.log(posts))
  .catch(err => console.error(err));   // ONE catch for all errors!

// Promise static methods
// Promise.all — all must succeed; fails fast on first rejection
Promise.all([
  fetch("/api/users"),
  fetch("/api/posts"),
  fetch("/api/comments")
]).then(([users, posts, comments]) => {
  // all three resolved
});

// Promise.allSettled — waits for ALL (regardless of success/fail)
Promise.allSettled([p1, p2, p3]).then(results => {
  results.forEach(r => {
    if (r.status === "fulfilled") console.log(r.value);
    else console.log(r.reason);
  });
});

// Promise.race — first to settle wins (resolve or reject)
Promise.race([
  fetch("/api/primary"),
  fetch("/api/backup"),
  new Promise((_, rej) => setTimeout(() => rej("Timeout"), 5000))
]).then(data => console.log(data));

// Promise.any — first to RESOLVE wins (ignores rejections)
// Rejects only if ALL reject (AggregateError)
Promise.any([p1, p2, p3]).then(first => console.log(first));

// Promise.resolve / reject (create instantly resolved/rejected)
Promise.resolve(42).then(v => console.log(v));  // 42
Promise.reject(new Error("fail")).catch(e => console.error(e));

// Promisify pattern
function readFilePromise(path) {
  return new Promise((resolve, reject) => {
    fs.readFile(path, "utf8", (err, data) => {
      if (err) reject(err);
      else resolve(data);
    });
  });
}
Interview Points:
• Promise is immutable once settled
• .then() always returns a new Promise
• Promise.all = parallel + fail fast; Promise.allSettled = parallel + wait all
• Promise.race = fastest wins; Promise.any = first success wins
• Unhandled promise rejections crash Node.js in newer versions

28. Currying & Partial Application Advanced

Currying ek technique hai jisme multi-argument function ko single-argument functions ki chain mein transform kiya jaata hai. Partial Application mein kuch arguments pehle se fix karte hain, baaki baad mein pass karte hain.

Theory — Key Points:
• Currying — f(a, b, c) → f(a)(b)(c); function ek argument leta hai, aur function return karta hai
• Partial Application — kuch arguments fix karo: multiply(2) → function jo baki args leta hai
• Currying vs Partial — currying har baar exactly 1 argument; partial mein koi bhi number
• Benefits — reusability (add5, double, multiply10), function composition, point-free style
• Auto-curry (generic) — curry(fn) helper function jo kisi bhi function ko curried bana de
• Lodash/Ramda — _.curry() / R.curry() built-in; FP libraries extensively use karte hain
• Real use case — event handlers, configurations: const logError = log("ERROR"); logError("msg")
• Closure basis — currying closures pe depend karta hai inner function outer args remember kare

// Generic curry function
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);              // enough args — call original
    }
    return function(...moreArgs) {
      return curried(...args, ...moreArgs);  // collect more args
    };
  };
}

curriedAdd(1, 2, 3);    // 6

29. Memoization Advanced

Memoization ek optimization technique hai jisme function ke results cache kiye jaate hain — same inputs ke liye dobara calculate nahi karna padta, cache se result milta hai. Expensive computations (fibonacci, API calls) ke liye bahut useful hai.

Theory — Key Points:
• Cache = Map — JSON.stringify(args) ko key banao → result store karo
• Cache hit — same args milein toh "Cache hit!" → stored result return karo, function mat chalao
• Pure functions only — memoization sirf pure functions ke liye kaam karta hai (same input → same output guaranteed)
• Trade-off — speed gain vs memory use; agar arguments unique hain toh cache beshkar fill hoga
• React.memo — React component memoization; useMemo → value memoize; useCallback → function memoize
• Fibonacci example — bina memo: O(2^n); memo ke saath: O(n) → dramatic speedup
• Cache invalidation — kab cache clear karein? Time-based, size-based ya manual (tricky problem)
• Lodash _.memoize — production-ready memoize function; custom resolver bhi support karta hai 
// Cache results of expensive function calls
function memoize(fn) {
  const cache = new Map();
  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      console.log("Cache hit!");
      return cache.get(key);
    }
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

// Example: expensive fibonacci
function fibonacci(n) {
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}
// fibonacci(40) — very slow!

const fastFib = memoize(function fib(n) {
  if (n <= 1) return n;
  return fastFib(n - 1) + fastFib(n - 2);  // uses memoized version
});
fastFib(40);  // fast!

// Closure-based memoization for single arg
function memoizeSimple(fn) {
  const cache = {};
  return function(arg) {
    if (arg in cache) return cache[arg];
    return (cache[arg] = fn(arg));
  };
}

30. Debounce & Throttle Advanced

Debounce aur Throttle performance optimization techniques hain jo frequent events (scroll, resize, keypress, mousemove) ke saath overuse of function calls ko control karte hain. Interview mein ye bahut common question hai.

Theory — Key Points:
• Debounce — user ruk jaaye PHIR execute karo; har keypress timer reset karta hai; sirf last call run hoti hai
• Throttle — regular intervals pe execute karo; bade mein se first call run hoti hai, baaki skip
• Debounce use cases — search input (API call), form validation, window resize handler
• Throttle use cases — scroll position tracking, mouse tracking, button spam prevention
• Key difference — Debounce: "pause ke baad ek baar"; Throttle: "X ms mein ek baar"
• clearTimeout — debounce mein timer clear karna hai pehle har call pe (nahin toh multiple timers chalenge)
• Leading vs Trailing — leading: pehli call turant; trailing: rukne ke baad (default debounce)
• Lodash — _.debounce(fn, ms) aur _.throttle(fn, ms) production mein common hai
• React Hook — useDebounce / useThrottle custom hooks mein wrap karo

Debounce — wait until user stops, THEN execute

// Use case: search input, resize, form validation
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);       // cancel previous timer
    timer = setTimeout(() => {
      fn.apply(this, args);    // execute after delay
    }, delay);
  };
}

const search = debounce((query) => {
  console.log("Searching:", query);
}, 500);

// User types: s → se → sea → sear → searc → search
// Only fires once, 500ms after "search" is typed
searchInput.addEventListener("input", e => search(e.target.value));

Throttle — execute at most once per interval

// Use case: scroll, mousemove, window resize, API rate limiting
function throttle(fn, limit) {
  let lastRun = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastRun >= limit) {
      lastRun = now;
      fn.apply(this, args);
    }
  };
}

const onScroll = throttle(() => {
  console.log("scroll position:", window.scrollY);
}, 200);  // at most once every 200ms

window.addEventListener("scroll", onScroll);

// Throttle: fires at regular intervals — no gaps

32. Regular Expressions Intermediate

Regular Expressions (Regex) patterns hain jo strings mein search, match, aur replace karne ke liye use hote hain. Form validation (email, phone, password) aur text processing mein ye bahut important hain.

Theory — Key Points:
• Literal vs Constructor — /pattern/flags (static) vs new RegExp("pattern", "flags") (dynamic string se)
• Flags — g (global, sab match), i (case-insensitive), m (multiline), s (dotAll), u (unicode)
• Character Classes — \d (digit), \w (word char), \s (space), \b (word boundary); uppercase = opposite
• Quantifiers — * (0+), + (1+), ? (0 or 1), {n} (exactly n), {n,m} (n to m); ? baad mein = lazy
• Anchors — ^ (string start), $ (string end); m flag ke saath line start/end pe bhi
• Groups — (abc) capturing group; (?:abc) non-capturing; (?<name>abc) named group
• test() vs match() — regex.test(str) → boolean; str.match(regex) → array ya null
• exec() — regex.exec(str) → detailed match array with index; g flag ke saath iterate karo
• replace(regex, fn) — powerful: match ke basis pe dynamically replace karo

    (this.#events[event] ??= []).push(listener);
    return () => this.off(event, listener);  // returns unsubscribe fn
  }

  off(event, listener) {
    this.#events[event] = (this.#events[event] || []).filter(l => l !== listener);
  }

  emit(event, ...args) {
    (this.#events[event] || []).forEach(l => l(...args));
  }

  once(event, listener) {
    const unsubscribe = this.on(event, (...args) => {
      listener(...args);
      unsubscribe();
    });
  }
}

class MyPromise {
  #state = "pending";
  #value = undefined;
  #handlers = [];

  constructor(executor) {
    const resolve = (value) => {
      if (this.#state !== "pending") return;
      this.#state = "fulfilled";
      this.#value = value;
      this.#handlers.forEach(h => h.onFulfilled(value));
    };
    const reject = (reason) => {
      if (this.#state !== "pending") return;
      this.#state = "rejected";
      this.#value = reason;
      this.#handlers.forEach(h => h.onRejected(reason));
    };
    try { executor(resolve, reject); }
    catch (e) { reject(e); }
  }

  then(onFulfilled, onRejected) {
    return new MyPromise((resolve, reject) => {
      const handle = (fn, val, fallback) => {
        queueMicrotask(() => {
          try {
            if (typeof fn !== "function") { fallback(val); return; }
            const result = fn(val);
            result instanceof MyPromise ? result.then(resolve, reject) : resolve(result);
          } catch (e) { reject(e); }
        });
      };
      if (this.#state === "fulfilled")  handle(onFulfilled, this.#value, resolve);
      else if (this.#state === "rejected") handle(onRejected, this.#value, reject);
      else this.#handlers.push({
        onFulfilled: v => handle(onFulfilled, v, resolve),
        onRejected:  r => handle(onRejected, r, reject)
      });
    });
  }

  catch(fn) { return this.then(undefined, fn); }
  finally(fn) {
    return this.then(
      val  => { fn(); return val; },
      err  => { fn(); throw err; }
    );
  }
  static resolve(val) { return new MyPromise(res => res(val)); }
  static reject(val)  { return new MyPromise((_, rej) => rej(val)); }
  static all(promises) {
    return new MyPromise((resolve, reject) => {
      const results = [];
      let remaining = promises.length;
      if (!remaining) return resolve([]);
      promises.forEach((p, i) => {
        MyPromise.resolve(p).then(val => {
          results[i] = val;
          if (--remaining === 0) resolve(results);
        }, reject);
      });
    });
  }

function deepClone(obj, seen = new WeakMap()) {
  if (obj === null || typeof obj !== "object") return obj;
  if (obj instanceof Date)   return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj.source, obj.flags);
  if (seen.has(obj))         return seen.get(obj);  // circular ref

  const clone = Array.isArray(obj)
    ? []
    : Object.create(Object.getPrototypeOf(obj));

  seen.set(obj, clone);

  for (const key of Reflect.ownKeys(obj)) {  // includes Symbol keys
    clone[key] = deepClone(obj[key], seen);
  }
  return clone;
}

2. EventEmitter

class EventEmitter {
  #events = new Map();

  on(event, listener) {
    if (!this.#events.has(event)) this.#events.set(event, []);
    this.#events.get(event).push(listener);
    return this;  // chainable
  }

  once(event, listener) {
    const wrapper = (...args) => { listener(...args); this.off(event, wrapper); };
    return this.on(event, wrapper);
  }

  off(event, listener) {
    const listeners = this.#events.get(event) || [];
    this.#events.set(event, listeners.filter(l => l !== listener));
    return this;
  }

  emit(event, ...args) {
    (this.#events.get(event) || []).slice().forEach(l => l(...args));
    return this;
  }
}

4. LRU Cache

class LRUCache {
  #capacity;
  #cache = new Map();  // Map preserves insertion order — key insight!

  constructor(capacity) { this.#capacity = capacity; }

  get(key) {
    if (!this.#cache.has(key)) return -1;
    const val = this.#cache.get(key);
    this.#cache.delete(key);   // move to end (most recently used)
    this.#cache.set(key, val);
    return val;
  }

  put(key, value) {
    if (this.#cache.has(key)) this.#cache.delete(key);
    if (this.#cache.size >= this.#capacity) {
      // Delete oldest entry (first key in Map)
      this.#cache.delete(this.#cache.keys().next().value);
    }
    this.#cache.set(key, value);
  }
}

async function retry(fn, retries = 3, delayMs = 1000) {
  for (let attempt = 0; attempt <= retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (attempt === retries) throw err;
      await new Promise(r => setTimeout(r, delayMs * Math.pow(2, attempt)));
    }
  }
}

8. Controlled Concurrency (AsyncQueue)

class AsyncQueue {
  #concurrency;
  #running = 0;
  #queue = [];

  constructor(concurrency = 1) { this.#concurrency = concurrency; }

  add(task) {
    return new Promise((resolve, reject) => {
      this.#queue.push({ task, resolve, reject });
      this.#run();
    });
  }

  #run() {
    while (this.#running < this.#concurrency && this.#queue.length) {
      const { task, resolve, reject } = this.#queue.shift();
      this.#running++;
      Promise.resolve(task())
        .then(resolve, reject)
        .finally(() => { this.#running--; this.#run(); });
    }
  }
}

50. Advanced Interview Q&A — Part 2

Q31. What is prototype pollution?
A: Attacker modifies Object.prototype so ALL plain objects inherit malicious props.
   e.g., JSON.parse('{"__proto__":{"admin":true}}') → {} becomes admin!
   Fix: Use Object.create(null), Object.hasOwn() not 'in', schema validation on untrusted input.

Q32. What is the difference between microtask and macrotask?
A: Microtasks: Promise.then/.catch/.finally, queueMicrotask(), MutationObserver
   Macrotasks: setTimeout, setInterval, I/O, UI events, requestAnimationFrame
   Rule: after EACH macrotask, ALL microtasks drain before the next macrotask.

Q33. Difference between Object.freeze() and const?
A: const: prevents variable REBINDING (the reference/binding, not the value)
   Object.freeze(): prevents property MODIFICATIONS (the value's contents)
   const obj = {}; obj.a = 1;  ✅  (const doesn't freeze the value)
   Object.freeze({}); obj.a = 1;  ❌  (silently fails or TypeError in strict)

Q34. What is Function.prototype.length?
A: Number of formal parameters BEFORE first default/rest parameter.
   function f(a, b, c = 1, ...d) {}.length === 2  (only a, b count)
   Used by curry() to know when enough arguments have been collected.

Q35. What is the difference between for...in and Object.keys()?
A: for...in: ALL enumerable props including INHERITED ones (prototype chain)
   Object.keys(): ONLY own enumerable properties
   Always use Object.keys() or for...in + hasOwnProperty to be safe.

Q36. How does structuredClone differ from JSON.parse(JSON.stringify())?
A: structuredClone: handles Date, RegExp, Map, Set, ArrayBuffer, circular refs
   JSON: loses Date (→ string), RegExp (→ {}), undefined, functions, Symbols
   Use structuredClone() for reliable deep cloning in modern environments.

Q37. What is tail call optimization (TCO)?
A: When a function's final action is calling another function, engines can
   reuse the current stack frame instead of creating a new one.
   Prevents stack overflow in deep recursion. JS spec requires TCO in strict
   mode, but very few engines (only JavaScriptCore/Safari) implement it.

Q38. What are tagged template literals?
A: Function called with template literal: tag`Hello ${name}`
   tag(strings, ...values) receives: strings = ["Hello ", ""], values = [name]
   Used in: sql`SELECT * FROM ${table}` (injection prevention), styled-components,
   i18n translation functions, syntax highlighting libraries.

Q39. Why does [] + {} equal "[object Object]" but {} + [] equals 0?
A: [] + {} : both treated as values — [] → "", {} → "[object Object]", concat → "[object Object]"
   {} + []  : at statement level, {} is parsed as empty BLOCK, not object literal
            so it becomes: {}  (block);  +[]  (unary plus on []) → +"" → 0

Q40. What is Optional Catch Binding?
A: In ES2019+, the error variable in catch is optional:
   try { JSON.parse(bad); } catch { console.log("Parse failed"); }
   Previously: catch (e) was required even if e was never used.

Q41. null vs undefined in function parameters?
A: undefined → TRIGGERS default parameter: function f(x=10) {}; f(undefined) → x=10
   null → does NOT trigger default: f(null) → x=null
   Key rule: only undefined triggers default parameter values.

Q42. What is Symbol.toPrimitive?
A: Customize how an object converts to a primitive value.
   obj[Symbol.toPrimitive] = function(hint) {
     if (hint === "number") return 42;
     if (hint === "string") return "myObj";
     return true;  // "default" hint
   };
   Hint is "number" (math ops), "string" (template/toString), "default" (+, ==)

Q43. What is the difference between Object.seal() and Object.freeze()?
A: Object.seal(): can MODIFY existing properties, but cannot ADD or DELETE
   Object.freeze(): cannot modify, add, or delete any properties (fully locked)
   Both are SHALLOW — nested objects are still mutable.

Q44. Explain the difference between == abstract equality algorithm steps for objects
A: object == primitive: object is converted via ToPrimitive (tries valueOf, then toString)
   [] == 0: [].valueOf()=[], [].toString()="", Number("")=0, 0==0=true
   This is why [] == false and [] == "" are both true.

Q45. What is WeakRef and when to use it?
A: WeakRef holds a reference that does NOT prevent garbage collection.
   ref.deref() returns the object or undefined if already collected.
   Use case: caching where you're OK if cache entry disappears.
   FinalizationRegistry runs a callback after the object is GC'd.

Q46. What are Labeled statements?
A: Labels allow break/continue to target specific outer loops.
   outer: for (let i = 0; i < 3; i++) {
     for (let j = 0; j < 3; j++) {
       if (j === 1) continue outer;  // skip to next i iteration
       if (i === 2) break outer;     // break outer loop entirely
     }
   }

Q47. What is the "arguments" object vs rest parameters?
A: arguments: array-like (not real Array), no arrow fns, includes ALL args
   rest (...params): real Array, only remaining args, works in arrow fns
   arguments.callee is deprecated; prefer named functions or rest params.

Q48. How does optional chaining work with function calls?
A: obj?.method()  — only calls method if obj is not null/undefined
   obj?.[expr]    — safe bracket notation
   fn?.()         — only calls fn if it's a function (not null/undefined)
   This prevents "Cannot read properties of null" errors.

Q49. What is the Proxy vs Object.defineProperty for reactivity?
A: defineProperty: intercepts only get/set of SPECIFIC predefined properties
   Proxy: intercepts ALL operations dynamically — new properties, delete, has, etc.
   Vue 2 used defineProperty (limitation: can't detect new prop additions)
   Vue 3 / modern frameworks use Proxy (detects everything, cleaner API)

Q50. What happens when you throw inside a finally block?
A: The finally block's throw REPLACES the original error — original is lost!
   try { throw new Error("original"); }
   finally { throw new Error("from finally"); }  // "original" is swallowed!
   Best practice: never throw inside finally. Use it only for cleanup.

PATTERN 8 — Array Deduplication (Set ↔ Array)

Pattern Samjho: Duplicate values hatana ek bahut common interview question hai. Set automatically unique values rakhta hai. new Set(arr) se Set banao, [...set] ya Array.from(set) se wapas array banao. 
// ─── Pattern 8: Array ↔ Set (Deduplication) ────────────────────────────────

let nums = [1, 2, 3, 2, 4, 3, 5, 1];
let strs = ["a", "b", "a", "c", "b", "d"];

// Basic deduplication
let uniqueNums = [...new Set(nums)];
console.log(uniqueNums); // [1, 2, 3, 4, 5]

let uniqueStrs = Array.from(new Set(strs));
console.log(uniqueStrs); // ["a", "b", "c", "d"]

// ─── Set Operations ─────────────────────────────────────────

let setA = new Set([1, 2, 3, 4]);
let setB = new Set([3, 4, 5, 6]);

// Union (dono ka combination)
let union = [...new Set([...setA, ...setB])];
console.log(union); // [1, 2, 3, 4, 5, 6]
// ya: new Set([...setA, ...setB]) directly

// Intersection (dono mein common)
let intersection = [...setA].filter(x => setB.has(x));
console.log(intersection); // [3, 4]

// Difference (A mein hai, B mein nahi)
let difference = [...setA].filter(x => !setB.has(x));
console.log(difference); // [1, 2]

// Symmetric Difference (sirf ek mein hai, dono mein nahi)
let symDiff = [
  ...[...setA].filter(x => !setB.has(x)),
  ...[...setB].filter(x => !setA.has(x))
];
console.log(symDiff); // [1, 2, 5, 6]

// ─── Object array deduplication by property ─────────────────
let users = [
  { id: 1, name: "Alice" },
  { id: 2, name: "Bob" },
  { id: 1, name: "Alice" },  // duplicate
  { id: 3, name: "Carol" }
];

// Method 1: Map se (order preserve karta hai)
let uniqueUsers = [...new Map(users.map(u => [u.id, u])).values()];
console.log(uniqueUsers);
// [{id:1,name:"Alice"}, {id:2,name:"Bob"}, {id:3,name:"Carol"}]
// Explanation: map se [id, user] pairs banaye, Map automatically duplicate ids overwrite karta hai

// Method 2: reduce se
let uniqueUsers2 = users.reduce((acc, user) => {

    acc.push(user); // tabhi push karo jab pehle se na ho
  }

console.log(hasAllUnique([1,2,2,4])); // false

PATTERN 9 — Array Flattening + Type Conversion

Pattern Samjho: Nested arrays ko flat banana. flat() ek level, flat(Infinity) sabse deep tak. flatMap() = map + flat (ek level). Phir type conversion bhi karni pad sakti hai. 
// ─── Pattern 9: Array Flattening + Type Conversion ─────────────────────────

let nested1 = [1, [2, 3], [4, [5, 6]]];
let nested2 = [1, [2, [3, [4, [5]]]]];

console.log(nested1.flat(2));     // [1, 2, 3, 4, 5, 6]    ← 2 levels flat

// sentences.map(s => s.split(" ")) → [["hello","world"],["foo","bar"]] ← nested
// flatMap ek step mein karta hai

// WAY 3: Manual flatten (recursion) — for older environments
function deepFlatten(arr) {

function twoSum(arr, target) {

  for (let i = 0; i < arr.length; i++) {
    let complement = target - arr[i]; // complement chahiye
    if (seen.has(complement)) {
      return [seen.get(complement), i]; // pair mila!
    }
    seen.set(arr[i], i); // current number map mein daalo
  }
  return null;
}

// ─── Safe JSON parse ─────────────────────────────────────
function safeParse(str, defaultVal = null) {
  try {
    return JSON.parse(str); // try karo parse karna
  } catch {
    return defaultVal;      // invalid JSON → default value return karo
  }
}
console.log(safeParse('{"a":1}')); // {a: 1}
console.log(safeParse("not json")); // null (default)
console.log(safeParse("invalid", {})); // {} (custom default)
